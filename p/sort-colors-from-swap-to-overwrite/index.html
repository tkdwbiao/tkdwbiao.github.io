从交换到涂色：深度拆解『颜色分类』的逻辑进化

2026-04-01 20:00
阅读时长: 3 分钟

[LeetCode 75. 颜色分类] 要求我们将仅含 0, 1, 2 的数组原地排序。这道题通常被称为“荷兰国旗问题”。大部分教材会教你三指针交换，但今天阿彪要分享一个更“暴力”也更优雅的解法：三层涂色覆盖法。

一、 基础阶段：分而治之（两趟扫描）

1. 思想 (Idea)

既然只有三种颜色，我们可以分两次处理：

  • 第一趟：利用双指针把所有的 2 甩到数组末尾。
  • 第二趟：在剩下的前半部分里，再用双指针把 0 甩到前面。

class Solution:
    def sortColors(self, nums: List[int]) -> None:
        def partition(left, right, target, move_to_end):
            while left <= right:
                if move_to_end:
                    while left <= right and nums[left] != target: left += 1
                    while left <= right and nums[right] == target: right -= 1
                else:
                    while left <= right and nums[left] == target: left += 1
                    while left <= right and nums[right] != target: right -= 1
                if left < right:
                    nums[left], nums[right] = nums[right], nums[left]
                    left, right = left + 1, right - 1
            return right

        # 第一趟：把 2 挪到最后，返回 2 区域的左边界
        last_idx = partition(0, len(nums) - 1, 2, True)
        # 第二趟：在剩下的部分把 0 挪到最前
        partition(0, last_idx, 0, False)

阿彪点评：这种方法虽然容易理解，但需要遍历两遍数组，且指针边界控制较为繁琐。

二、 进阶阶段：三层涂色覆盖法（天才解法）🌟

这是阿彪在练习中发现的一个极简思路。它不再纠结如何“交换”，而是利用顺序覆盖来重新定义边界。

1. 思想 (Idea)

想象你在排队，每来一个人，我们都经历三层逻辑判定：

  1. 无差别占位：先假设他是最后面的蓝色（2），在总队尾写下 2。
  2. 中间层修正：如果原数其实是 0 或 1，说明刚才占位的 2 多了，我们在白色（1）的边界处改写为 1。
  3. 最前层修正：如果原数真的是 0，说明前面的白色也多了，我们在红色（0）的边界处改写为 0。

2. 过程图解：以 [0, 1, 0, 2] 为例

初始指针：r=0, w=0, b=0

  • 读取 0：
    • nums[b=0]=2, b=1 $\to$ [2]
    • 0 < 2 成立：nums[w=0]=1, w=1 $\to$ [1]
    • 0 < 1 成立：nums[r=0]=0, r=1 $\to$ [0]
  • 读取 1：
    • nums[b=1]=2, b=2 $\to$ [0, 2]
    • 1 < 2 成立：nums[w=1]=1, w=2 $\to$ [0, 1]
    • 1 < 1 ❌
  • 读取 0：
    • nums[b=2]=2, b=3 $\to$ [0, 1, 2]
    • 0 < 2 成立：nums[w=2]=1, w=3 $\to$ [0, 1, 1]
    • 0 < 1 成立：nums[r=1]=0, r=2 $\to$ [0, 0, 1]
  • 读取 2：
    • nums[b=3]=2, b=4 $\to$ [0, 0, 1, 2]
    • 2 < 2 ❌

结论：通过 2 $\to$ 1 $\to$ 0 的顺序覆盖，小浪总能精准覆盖大浪，实现自动排序。

class Solution:
    def sortColors(self, nums: List[int]) -> None:
        # r, w, b 分别代表 0, 1, 2 区域的待插入位置（即当前长度）
        r = w = b = 0
        for num in nums:
            # 必须备份原值，因为 nums[b] 可能正在改写它
            tmp = num
            
            # 第一层：铺底色 2
            nums[b] = 2
            b += 1
            
            # 第二层：如果原数是 0 或 1，覆盖为 1
            if tmp < 2:
                nums[w] = 1
                w += 1
                
            # 第三层：如果原数是 0，覆盖为 0
            if tmp < 1:
                nums[r] = 0
                r += 1

三、 阿彪的深度总结 [抱拳]

1. 为什么这个解法是“降维打击”？

传统的“荷兰国旗”交换法需要处理 while 嵌套和复杂的 if-else 分支，稍不留神就会漏掉换回来的那个数。 而覆盖法将逻辑拉平：

  • 无脑赋值：通过 $r \le w \le b$ 的数学不等式，保证了赋值的安全性。
  • CPU 友好：顺序写入对缓存极其友好，且没有复杂的分支预测负担。

2. 复杂度分析

  • 时间复杂度：$O(n)$。只扫一遍，每个位置最多被写 3 次。
  • 空间复杂度：$O(1)$。只用了三个整数变量。

3. 面试话术建议

“面试官，这道题的常规解法是三指针交换。但我采用了一种基于**‘边界推行与覆盖’**的策略。通过按 2、1、0 的优先级顺序进行重写，我利用赋值操作的原子性避开了复杂的交换逻辑判断。这种方法代码鲁棒性更高，且充分利用了顺序访问的性能优势。”
