二叉树路径搜索：从 $O(n^2)$ 双重递归到 $O(n)$ 前缀和的华丽转身

2026-03-31 14:30
阅读时长: 3 分钟

在 LeetCode 437. 路径总和 III 中，路径不一定从根节点开始，也不一定在叶子节点结束。这种“任意连续区间”的求和问题，是考察算法优化能力的绝佳题目。

今天阿彪带大家拆解三种解法，看透背后的逻辑演进。

一、 方法一：阿彪的初版尝试（副作用与缓存陷阱）

1. 核心思想

利用两个 DFS 函数：外层遍历每个节点作为起点，内层以该点向下搜索。

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        res = 0
        cur_val = 0
        # @cache  <-- ⚠️ 坑在这里！
        def dfs(node):
            nonlocal res, cur_val
            if not node: return
            cur_val += node.val
            if cur_val == targetSum:
                res += 1  # 产生了副作用（Side Effect）
            dfs(node.left)
            dfs(node.right)
            cur_val -= node.val # 回溯
        
        def dfs2(node):
            if not node: return
            dfs(node)
            dfs2(node.left)
            dfs2(node.right)
        
        dfs2(root)
        return res

💡 阿彪的反思：为什么不能加 @cache？

@cache 只对纯函数有效。由于 dfs 内部修改了外部变量 res，缓存机制会认为对于同一个 node 已经跑过了，第二次调用时会直接跳过函数体返回 None。结果就是：内部的 res += 1 被偷走了！

二、 方法二：标准双重递归（扫描仪 vs 探险家）

1. 核心思想

将逻辑纯粹化：

  • 主函数（扫描仪）：递归遍历树的每一个节点。
  • 辅函数（探险家）：只负责从当前点出发，向下寻找和为 target 的路径。

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        def dfs(node, remain):
            if not node: return 0
            # 当前点是否达标 + 左子树结果 + 右子树结果
            count = 1 if node.val == remain else 0
            count += dfs(node.left, remain - node.val)
            count += dfs(node.right, remain - node.val)
            return count

        if not root: return 0
        # 扫描仪逻辑：以我为起点 + 递归左子树 + 递归右子树
        return dfs(root, targetSum) + \
               self.pathSum(root.left, targetSum) + \
               self.pathSum(root.right, targetSum)
  • 复杂度分析：时间 $O(n^2)$，空间 $O(n)$。

三、 方法三：极致优化（前缀和 + 哈希表）🌟

1. 核心思想：寻找“差值”的艺术

我们将数组中“和为 K 的子数组”思想迁移到树上。

  • 树的前缀和：从根节点到当前节点的累加和。
  • 数学推导：我们要找祖先里有多少个 $prev\_sum$ 满足： $$curr\_sum - prev\_sum = targetSum \implies prev\_sum = curr\_sum - targetSum$$

2. 举例说明

假设 targetSum = 8，路径：10 -> 5 -> 3。

  • 走到节点 10：Map 存 {10:1}。
  • 走到节点 5：curr_sum=15。查 15-8=7，无。Map 存 {15:1}。
  • 走到节点 3：curr_sum=18。查 18-8=10。
  • 命中！ 节点 10 就在祖先里，说明从 10 之后到 3 这一段路径和为 8。

from collections import defaultdict

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        # 1. 前缀和哈希表：{前缀和 : 出现次数}
        # 初始化 0:1，处理从根节点开始就正好等于 targetSum 的情况
        prefix_map = defaultdict(int)
        prefix_map[0] = 1
        
        def dfs(node, cur_sum):
            if not node: return 0
            
            cur_sum += node.val # 累加当前路径和
            
            # 2. 核心：查表。看有多少个祖先能跟我们凑成目标
            count = prefix_map[cur_sum - targetSum]
            
            # 3. 存表：给子孙节点查
            prefix_map[cur_sum] += 1
            
            # 4. 递归左右子树
            count += dfs(node.left, cur_sum)
            count += dfs(node.right, cur_sum)
            
            # 5. 【关键回溯】：离开节点前，撤销当前记录
            # 确保哈希表里永远只存当前节点的“直系祖先”
            prefix_map[cur_sum] -= 1
            
            return count

        return dfs(root, 0)

四、 阿彪的深度总结 [抱拳]

  1. 逻辑迁移：本题是 LeetCode 560. 和为 K 的子数组 的树形版。
  2. 回溯的物理意义：在树上，哈希表是动态的。**“进门加记录，出门减记录”**是防止左子树污染右子树的唯一手段。
  3. 初始化 0:1：这是为了处理“从头开始”的路径，绝对不能忘。

  3. LeetCode 974. 和可被 K 整除的子数组：前缀和 + 取模 + 哈希表。
