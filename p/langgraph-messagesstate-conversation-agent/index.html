LangGraph 实战笔记 10：构建有记忆的多轮对话 Agent

2025-11-19 10:00
阅读时长: 11 分钟

上一篇文章里，我们讲了如何构建可靠的长流程 Agent。

重点是：

1
2
3
4

interrupt 负责暂停。
resume 负责恢复。
checkpoint 负责保存状态。
thread_id 负责标识一条可恢复的执行线程。

这一篇，我们进入另一个非常核心的场景：多轮对话 Agent。

一个真正可用的对话 Agent，不能每次都像第一次见到用户一样。

它需要记住前面的消息，理解上下文，并在后续回答中继续沿用已有信息。

在 LangGraph 里，对话记忆的核心不是传统意义上的 Memory 对象，而是图状态中的 messages。

也就是这一篇要重点讲的：MessagesState。

一、前言

在前面的 LangChain 系列里，我们已经讲过 Memory。

传统 Memory 的核心问题是：

如何让模型在多轮对话中看到历史消息？

比如：

1
2
3
4

用户：我叫阿彪。
助手：你好，阿彪。
用户：我叫什么？
助手：你叫阿彪。

如果没有记忆，第二次提问时模型并不知道“我叫阿彪”。

在 LangChain 里，我们通常会通过某种 Memory 或 chat history 把历史消息拼进 Prompt。

到了 LangGraph，思路会更工程化一些。

LangGraph 本身就是有状态图。

所以多轮对话历史可以直接成为 State 的一部分。

例如：

1

messages: list

每一轮用户输入、模型回复、工具结果，都作为消息追加到这个列表里。

这样，Agent 的“记忆”不再是一个隐藏在链外面的对象，而是图状态的一部分。

这也是 LangGraph 和普通 Chain 的一个重要区别。

二、为什么多轮对话需要 MessagesState？

先看一个没有记忆的调用。

1
2

answer = model.invoke("我叫阿彪")
answer = model.invoke("我叫什么？")

第二次调用时，模型只看到：

1

我叫什么？

它不知道上一轮用户说过什么。

多轮对话需要把历史传进去：

1
2
3
4
5
6
7

messages = [
    HumanMessage(content="我叫阿彪"),
    AIMessage(content="你好，阿彪"),
    HumanMessage(content="我叫什么？"),
]

answer = model.invoke(messages)

这样模型才有上下文。

但在 Agent 中，消息不仅包括用户和助手。

还可能包括工具调用相关消息：

1
2
3
4

HumanMessage：用户问题
AIMessage：模型决定调用工具
ToolMessage：工具返回结果
AIMessage：模型基于工具结果回答

如果手动维护这些消息列表，很容易出错。

LangGraph 的 MessagesState 就是为这种场景准备的。

它让 messages 成为图状态的一部分，并通过 reducer 自动追加新消息。

三、LangChain Message 对象回顾

在 LangChain / LangGraph 生态里，对话通常由 Message 对象表示。

常见类型包括：

类型含义
HumanMessage用户消息
AIMessage模型回复
SystemMessage系统指令
ToolMessage工具执行结果

示例：

1
2
3
4
5
6
7
8

from langchain_core.messages import HumanMessage, AIMessage, SystemMessage


messages = [
    SystemMessage(content="你是一个清晰、严谨的助手。"),
    HumanMessage(content="LangGraph 是什么？"),
    AIMessage(content="LangGraph 是一个用于构建有状态 Agent 工作流的框架。"),
]

这些 Message 对象比普通字符串更结构化。

模型可以区分：

  • 哪些内容来自用户。
  • 哪些内容来自助手。
  • 哪些内容是系统指令。
  • 哪些内容是工具结果。

对 Agent 来说，这种结构化非常重要。

因为工具调用、多轮对话、消息追踪和调试都依赖它。

四、MessagesState 是什么？

MessagesState 是 LangGraph 提供的一个常用 State 类型。

它默认包含一个 messages 字段。

这个字段用来保存对话历史。

最简单的写法：

1
2
3
4
5

from langgraph.graph import MessagesState


class ChatState(MessagesState):
    pass

你也可以在它基础上增加业务字段：

1
2
3
4
5
6

from langgraph.graph import MessagesState


class ChatState(MessagesState):
    user_name: str
    intent: str

这样 State 里既有：

1

messages

也有：

1
2

user_name
intent

这很适合真实 Agent。

因为真实 Agent 往往既需要消息历史，也需要结构化业务状态。

例如：

1
2
3
4

class SupportState(MessagesState):
    user_id: str
    order_id: str
    needs_human_review: bool

五、add_messages：为什么消息是追加而不是覆盖？

在普通 State 字段中，节点返回同名字段时通常表示覆盖。

例如：

1

return {"answer": "新的回答"}

会覆盖旧的 answer。

但对 messages 来说，我们通常不希望覆盖历史。

我们希望追加：

1

已有消息 + 新消息

这就需要 reducer。

在 LangGraph 中，MessagesState 内部已经为 messages 配好了类似 add_messages 的追加逻辑。

如果自己定义，也可以这样写：

1
2
3
4
5
6
7

from typing import Annotated, TypedDict
from langchain_core.messages import AnyMessage
from langgraph.graph.message import add_messages


class ChatState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]

含义是：

当节点返回新的 messages 时，不是覆盖历史，而是把新消息追加进去。

例如当前 State 是：

1
2
3

{
    "messages": [HumanMessage(content="你好")]
}

节点返回：

1
2
3

{
    "messages": [AIMessage(content="你好，我是助手")]
}

最终 State 会变成：

1
2
3
4
5
6

{
    "messages": [
        HumanMessage(content="你好"),
        AIMessage(content="你好，我是助手"),
    ]
}

这就是 MessagesState 最重要的价值。

六、最小多轮对话图

下面写一个最小的多轮对话图。

它只有一个节点：读取历史消息，然后追加一条助手回复。

 1
 2

from langchain_core.messages import AIMessage, HumanMessage
from langgraph.graph import MessagesState, StateGraph, START, END


class ChatState(MessagesState):
    pass


def chat_node(state: ChatState):
    last_message = state["messages"][-1]
    response = AIMessage(content=f"你刚才说：{last_message.content}")
    return {"messages": [response]}


builder = StateGraph(ChatState)

builder.add_node("chat", chat_node)
builder.add_edge(START, "chat")
builder.add_edge("chat", END)

graph = builder.compile()

result = graph.invoke({
    "messages": [HumanMessage(content="你好")]
})

print(result["messages"][-1].content)

输出类似：

1

你刚才说：你好

这个例子非常简单。

但它展示了 MessagesState 的基本模式：

1
2
3
4
5

输入 HumanMessage
  ↓
节点返回 AIMessage
  ↓
messages 自动追加

最终 messages 中同时包含用户消息和助手消息。

八、配合 checkpoint 实现跨轮记忆

仅仅使用 MessagesState，可以在一次图调用内部保存消息。

但如果你希望多次调用之间也记住历史，就需要 checkpoint。

也就是：

1
2
3

第一次调用：用户说“我叫阿彪”
第二次调用：用户问“我叫什么？”
系统仍然能记住上一轮

这需要：

  1. 编译图时提供 checkpointer。
  2. 每次调用使用同一个 thread_id。

示例：

from langchain_core.messages import HumanMessage
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import MessagesState, StateGraph, START, END


class ChatState(MessagesState):
    pass


model = ChatOpenAI(model="gpt-4o-mini", temperature=0)


def chatbot_node(state: ChatState):
    response = model.invoke(state["messages"])
    return {"messages": [response]}


builder = StateGraph(ChatState)
builder.add_node("chatbot", chatbot_node)
builder.add_edge(START, "chatbot")
builder.add_edge("chatbot", END)

checkpointer = InMemorySaver()
graph = builder.compile(checkpointer=checkpointer)

config = {"configurable": {"thread_id": "chat-user-1"}}

graph.invoke(
    {"messages": [HumanMessage(content="我叫阿彪")]},
    config=config,
)

result = graph.invoke(
    {"messages": [HumanMessage(content="我叫什么？")]},
    config=config,
)

print(result["messages"][-1].content)

因为两次调用使用同一个 thread_id，checkpointer 会把它们视为同一段对话。

第二次调用时，历史消息还在 State 中。

这就是 LangGraph 中的多轮记忆。

九、MessagesState 和传统 Memory 的区别

LangChain 里的 Memory 通常是链外部的记忆组件。

它负责在调用前加载历史，在调用后保存新消息。

LangGraph 的思路更像：

对话历史就是图状态的一部分。

可以简单对比一下：

对比项传统 LangChain MemoryLangGraph MessagesState
记忆位置Chain 外部组件Graph State 的一部分
历史形式通常是 chat historymessages 状态字段
状态恢复依赖 Memory 实现依赖 checkpointer 和 thread_id
工具消息需要额外处理可和 Agent 消息流统一管理
流程控制不直接表达流程可与节点、边、checkpoint 结合

这并不是说传统 Memory 没用。

而是在 LangGraph 中，推荐把 Agent 执行所需的状态显式放进图状态里。

这样更容易观察、恢复和调试。

十一、一个带路由的多轮对话 Agent

from typing import Literal
from langchain_core.messages import AIMessage, HumanMessage
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import MessagesState, StateGraph, START, END


class SupportState(MessagesState):
    intent: str
    order_status: str


def classify_node(state: SupportState):
    last_message = state["messages"][-1].content

    if "订单" in last_message or "物流" in last_message:
        return {"intent": "order"}

    return {"intent": "chat"}


def route_by_intent(state: SupportState) -> Literal["order", "chat"]:
    return state["intent"]


def query_order_node(state: SupportState):
    return {"order_status": "订单 1001 当前状态：已发货，物流运输中。"}


def answer_order_node(state: SupportState):
    response = AIMessage(content=state["order_status"])
    return {"messages": [response]}


def chat_node(state: SupportState):
    response = AIMessage(content="你好，我可以帮你查询订单，也可以回答常见问题。")
    return {"messages": [response]}


builder = StateGraph(SupportState)

builder.add_node("classify", classify_node)
builder.add_node("query_order", query_order_node)
builder.add_node("answer_order", answer_order_node)
builder.add_node("chat", chat_node)

builder.add_edge(START, "classify")
builder.add_conditional_edges(
    "classify",
    route_by_intent,
    {
        "order": "query_order",
        "chat": "chat",
    },
)
builder.add_edge("query_order", "answer_order")
builder.add_edge("answer_order", END)
builder.add_edge("chat", END)

checkpointer = InMemorySaver()
graph = builder.compile(checkpointer=checkpointer)

config = {"configurable": {"thread_id": "support-user-1"}}

result = graph.invoke(
    {"messages": [HumanMessage(content="帮我查一下订单 1001 的物流")]},
    config=config,
)

print(result["messages"][-1].content)

输出类似：

1

订单 1001 当前状态：已发货，物流运输中。

这里同时使用了：

  • MessagesState 保存对话历史。
  • intent 保存路由字段。
  • order_status 保存工具结果。
  • checkpointer 保存跨轮状态。

十二、ToolMessage 在 Agent 中的作用

多轮对话 Agent 如果涉及工具调用，就会遇到 ToolMessage。

一般流程是：

1
2
3
4

HumanMessage：用户问题
AIMessage：模型提出 tool call
ToolMessage：工具返回结果
AIMessage：模型基于工具结果回答

ToolMessage 表示工具执行结果。

它通常需要和前面的 tool call 对应。

简化示例：

1
2
3
4
5
6
7

from langchain_core.messages import AIMessage, ToolMessage


tool_result = ToolMessage(
    content="订单 1001 当前状态：已发货",
    tool_call_id="call_123",
)

这里的 tool_call_id 用来对应模型发起的某次工具调用。

在真实 Tool Calling 中，模型生成的 AIMessage 里会包含 tool calls。

工具执行后，需要把对应的 ToolMessage 加回 messages。

如果消息顺序不正确，例如有 tool call 却没有对应 ToolMessage，就可能出现无效聊天历史错误。

所以工具调用型 Agent 要特别注意消息顺序。

后面讲 Tool Calling 和 ReAct Agent 时，我们会更系统地展开。

十三、消息历史会不会越来越长？

会。

这是多轮对话 Agent 必须面对的问题。

如果每一轮都把完整 messages 发给模型，随着对话变长，会遇到：

  • token 成本上升。
  • 上下文超过模型窗口。
  • 历史噪声影响回答。
  • 检索和工具结果堆积太多。

常见处理方式包括：

1. 保留最近 N 轮

只把最近几轮对话传给模型。

2. 总结旧历史

把较早的消息总结成摘要，再保留摘要和近期消息。

3. 结构化关键事实

把重要事实提取到 State 字段中。

例如：

1
2
3

user_name: str
user_preference: str
current_order_id: str

不要所有信息都只依赖 messages。

4. 按需检索历史

如果历史很多，可以把对话历史向量化，需要时检索相关片段。

这一篇先不展开长期记忆问题。

但要记住：

MessagesState 解决的是消息如何进入图状态，不等于解决了无限上下文问题。

十四、MessagesState 的常见问题

1. 每次覆盖 messages

如果你自己定义 State，却没有使用 add_messages，可能会把历史覆盖掉。

推荐使用：

1

MessagesState

或者：

1

messages: Annotated[list[AnyMessage], add_messages]

2. 忘记使用 checkpointer

MessagesState 只定义状态结构。

如果你希望跨多次调用保存对话历史，还需要 checkpointer。

3. 每次调用使用不同 thread_id

多轮对话要复用同一个 thread_id。

否则每次都是新的对话线程。

4. 把所有业务状态都塞进 messages

messages 很重要，但不要滥用。

如果某个信息需要程序判断，最好放进结构化字段。

例如：

1
2
3

intent: str
order_id: str
needs_human_review: bool

5. ToolMessage 顺序不正确

如果模型发起工具调用，后面要有对应工具结果消息。

否则可能形成无效聊天历史。

6. 历史消息无限增长

多轮对话要考虑上下文管理。

尤其是生产环境，不要无限把所有历史都塞给模型。

十五、最佳实践

1. 对话型 Agent 优先使用 MessagesState

如果你的 Agent 以消息历史为核心，MessagesState 是最直接的选择。

2. 跨轮记忆配合 checkpointer

同一个用户会话使用稳定 thread_id。

1

config = {"configurable": {"thread_id": "user-123"}}

3. 结构化状态和 messages 结合使用

不要让 messages 承担所有状态职责。

路由、控制、业务字段最好结构化。

4. 节点返回新增消息列表

常见模式是：

1

十六、总结

本文讲了如何用 LangGraph 构建有记忆的多轮对话 Agent。

核心结论是：

在 LangGraph 中，对话记忆不是隐藏在链外部的 Memory，而是图状态中的 messages。MessagesState 让消息历史成为可观察、可恢复、可路由的状态数据。

本文重点包括：

  • 多轮对话需要保存历史消息，否则模型无法理解上下文。
  • LangChain / LangGraph 使用 HumanMessage、AIMessage、SystemMessage、ToolMessage 表示不同消息角色。
  • MessagesState 默认包含 messages 字段，适合对话型 Agent。
  • add_messages 的核心作用是追加消息，而不是覆盖历史。
  • 接入 Chat Model 时，节点读取 state["messages"]，返回新的 AIMessage。
  • 跨轮记忆需要配合 checkpointer 和稳定的 thread_id。
  • MessagesState 可以和结构化业务字段一起使用。
  • 工具调用场景要注意 AIMessage tool call 与 ToolMessage 的对应关系。
  • 多轮对话还需要考虑历史消息增长和上下文管理。
