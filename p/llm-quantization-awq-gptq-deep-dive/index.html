从分格子到极值保护：深度拆解大模型量化与 AWQ/GPTQ 算法

2026-04-06 15:30
阅读时长: 7 分钟

在准备大模型（LLM）开发岗位的面试时，“量化（Quantization）”是一道绝对绕不过去的坎。很多同学只知道“把 FP16 变成 INT4 能省显存”，但一旦面试官追问“如何处理离群值？”、“AWQ和GPTQ的核心差异是什么？”，往往就哑口无言了。今天阿彪就带你从最基础的“分格子”理论开始，深度拆解工业界主流的量化落地方案。

一、 知识点详解：量化的本质与进阶

1. 基础概念：FP16 到 INT4 到底发生了什么？

大模型的权重默认通常是 FP16（半精度浮点数），每个参数占 16个 bit。而 INT4（4位整数） 只有 4个 bit，最多只能表示 $2^4 = 16$ 个状态（即 0 到 15）。

量化的本质，就是把高精度的数据，映射到这 16 个格子里。这个过程分为两步：

  • 量化（Quantize）：先找出一组权重的最大值（Max）和最小值（Min）。计算出每个格子的步长 Scale = (Max - Min) / 15。然后把 FP16 的数值除以 Scale，四舍五入放到最近的格子里，返回 0-15 的索引。
  • 反量化（Dequantize）：GPU 在计算时，INT4 是没法直接做高精度矩阵乘法的，需要用 索引 * Scale + Min 把数值还原成 FP16。

精度损失的来源：因为你做了“四舍五入”，反量化回来的数值和原来的 FP16 数值会有微小的差值，这就是量化误差。

2. 为什么 LLM 极难量化？（离群值问题）

传统的 CNN 模型很容易量化到 INT8 甚至 INT4，但大模型不行。因为大模型随着参数量增大（特别是超过 6B 以后），其 激活值（Activation） 中会出现极少数非常大的数值，我们称为 Outliers（离群值）。
如果按照常规的 Min-Max 来分格子，为了包容这些极大的 Outliers，Scale 会被拉得非常大，导致 99% 正常的数值被挤压在 1-2 个格子里，丧失了区分度，模型性能直接崩溃。

3. 破局之道：GPTQ 算法思想

GPTQ（Generalized Post-Training Quantization） 的核心思想是：“误差补偿”。 它不是孤立地去量化每一个权重，而是把同一层的所有权重当成一个整体。

  • 当把权重 $W_1$ 塞进格子产生量化误差 $\Delta W_1$ 时，GPTQ 不会忽略这个误差。
  • 它通过计算该层权重的 Hessian 矩阵的逆，找出权重之间的相关性。
  • 然后把 $W_1$ 的误差 $\Delta W_1$ 按照数学关系，平摊/补偿到还没有被量化的 $W_2, W_3$ 身上。
  • 通俗比喻：就像团队凑钱买单，A 没带够钱（产生误差），GPTQ 会精准计算出 B 和 C 应该多出多少钱（补偿），以保证总金额（最终的输出激活值）不变。

4. 破局之道：AWQ 算法思想

AWQ（Activation-aware Weight Quantization） 的视角更加独特，它认为：权重也是分三六九等的。

  • 团队发现，模型里大概只有 1% 的权重（Salient Weights） 对最终的输出起着决定性作用，这些权重往往对应着极大的激活值。
  • AWQ 怎么做？它在量化前，先把这 1% 的核心权重乘以一个放大因子 $s$ (Scale up)，同时把对应的输入激活值除以 $s$（保持数学等价：$W \cdot X = (W \cdot s) \cdot (X / s)$）。
  • 核心权重被放大后，在“分格子”时就能占据更多的刻度，量化误差相对就变小了（极值保护）。剩下的 99% 权重则正常粗糙量化。

import numpy as np

# 1. 基础的分格子（Min-Max 线性量化）
def basic_quantize(weights, bits=4):
    q_max = (1 << bits) - 1
    min_val, max_val = np.min(weights), np.max(weights)
    scale = (max_val - min_val) / q_max
    zero_point = round(-min_val / scale)
    
    # 放入格子并截断
    q_weights = np.round(weights / scale) + zero_point
    q_weights = np.clip(q_weights, 0, q_max)
    
    # 反量化还原
    deq_weights = (q_weights - zero_point) * scale
    return deq_weights

# 2. 模拟 AWQ：保护显著权重 (Salient Weights)
def awq_mock_quantize(weights, activations, bits=4):
    # 假设激活值最大的位置，对应的权重最重要
    salient_idx = np.argmax(np.abs(activations))
    
    # 将显著权重放大 (这里假设放大因子为 2)
    s = 2.0
    weights_scaled = weights.copy()
    weights_scaled[salient_idx] *= s
    
    # 对放大后的权重进行基础量化
    deq_weights_scaled = basic_quantize(weights_scaled, bits)
    
    # 反量化后，把之前放大的权重缩放回来
    deq_weights_scaled[salient_idx] /= s
    
    return deq_weights_scaled

# --- 阿彪的测试 ---
# 假设我们有一组权重，其中 0.5 是极其重要的权重（对应的激活值很大）
weights = np.array([0.1, 0.2, 0.5, 3.0]) 
activations = np.array([1.0, 1.0, 10.0, 1.0]) # 0.5 对应的激活值是 10.0，是离群值

print(f"原始权重: {weights}")

# 使用基础量化
deq_basic = basic_quantize(weights)
print(f"基础量化后: {deq_basic} (核心权重 0.5 变成了 {deq_basic[2]:.3f})")

# 使用模拟 AWQ量化
deq_awq = awq_mock_quantize(weights, activations)
print(f"AWQ模拟量化后: {deq_awq} (核心权重 0.5 变成了 {deq_awq[2]:.3f})")

代码点评：你可以看到，在基础量化中，因为有了 3.0 这个大值，导致 0.5 的精度损失很大。而在 AWQ 模拟中，我们提前放大了核心权重，使得反量化后它的精度得到了更好的保留。

三、 工业界的一些做法

在真正的企业落地中，量化绝不仅仅是跑个脚本那么简单。工业界通常有以下几种成熟的做法：

  1. PTQ (Post-Training Quantization) 训练后量化：
    • 这是目前最主流的做法（AWQ和GPTQ都属于此类）。模型训练完后，只需要少量的高质量校准数据（Calibration Data，比如 128 条维基百科文本），跑个几十分钟就能量化完毕，成本极低。
  2. Weight-Only (仅权重量化) vs W8A8：
    • Weight-Only (如 W4A16)：权重存为 INT4，计算时激活值是 FP16。它解决的是 “显存墙” 和 “内存带宽” 问题。因为推理时大部分时间花在把权重从显存搬到 GPU 计算单元上。体积缩小 4 倍，搬运速度就快 4 倍。
    • W8A8 (权重和激活值同量化)：主要解决 “计算墙” 问题。利用 GPU 的 Tensor Core 进行纯 INT8 矩阵相乘，算力直接翻倍。目前 SmoothQuant 是 W8A8 的主流方案。
  3. 推理框架的适配：
    • 工业界通常使用 vLLM 或 TensorRT-LLM 来部署量化模型。目前 vLLM 对 AWQ 的支持非常好，因为它不需要像 GPTQ 那样在推理时做复杂的反向补偿计算，算子（Kernel）实现起来更高效。

四、 面试官会问到的问题及详细答案

作为研二的学生，面试官往往会通过以下问题来深挖你的底层基本功：

❓ Q1：为什么现在大厂部署 LLM 首选 AWQ 而不是 GPTQ？

答： 主要有三个维度的考量：

  1. 重构成本：GPTQ 依赖 Hessian 矩阵的计算，校准时间较长。而 AWQ 只需要分析 Activation 的分布，量化速度更快。
  2. 硬件友好度（核心）：GPTQ 的误差补偿机制会导致在写 CUDA Kernel 时存在一定的访存开销（Mixed-precision overhead）。而 AWQ 本质上是对权重做了一次 Scaling 预处理，它保留了纯粹的 Weight-Only 结构，在 vLLM 等框架中可以直接复用高效的 W4A16 算子，因此 AWQ 的实际推理吞吐量（Throughput）通常比 GPTQ 更高。
  3. 精度保留：在极低比特（如 3-bit）或小参数模型下，AWQ 对上下文连贯性的保护通常优于 GPTQ。

❓ Q2：如果在推理时，用户输入的 Prompt 非常长，Weight-Only 量化（如 INT4）还能起到加速作用吗？

答： 不能，甚至可能变慢。 这是一个非常经典的“Memory Bound vs Compute Bound”问题。

  • 当批量较小（Batch Size=1）或处于 Decode 阶段（逐字生成）时，系统瓶颈在于把权重从显存读出来的速度（Memory Bound），此时 INT4 因为体积小，能大幅加速。
  • 但是，当输入 Prompt 极长（Prefill 阶段），或者 Batch Size 极大时，计算量呈平方级暴增，系统瓶颈转变为 GPU 的矩阵乘法算力（Compute Bound）。此时 Weight-Only 模型在计算前必须先执行“Dequantize（反量化转回 FP16）”，这额外增加了反量化的开销，导致速度反而不如纯 FP16。

❓ Q3：算力评估：部署一个 Llama-3-8B 模型，FP16 和 INT4 分别需要多大的显存？

答：

  • FP16：8 Billion 参数 × 2 Bytes/参数 ≈ 16 GB 显存。
  • INT4：8 Billion 参数 × 0.5 Bytes/参数 ≈ 4 GB 显存。
  • 实际部署：还需要考虑 KV Cache 和系统上下文的开销，通常 INT4 部署 8B 模型需要至少 6-8GB 显存（如 RTX 4060），而 FP16 则需要 20-24GB 显存（如 RTX 3090 / 4090）。

五、 总结

量化技术是大模型从“实验室”走向“千行百业”的基石。从最基础的 Min-Max 分格子，到 GPTQ 的 Hessian 矩阵误差补偿，再到 AWQ 的 激活感知极值保护，这本质上是一场数学与计算机体系结构的博弈。
对于面试而言，掌握“术”（如何调用 transformers/AutoAWQ 库）是基础，但理解其“道”（Outliers 的分布、Memory Bound 的转换、精度与速度的 Trade-off）才是让你在众多候选人中脱颖而出的关键。
