大模型时代的数据采集工程 39：WebDriver 检测机制与合规应对教程

2026-02-25 10:00
阅读时长: 23 分钟

前面第 37 篇，我们整理了 Selenium + Chrome 浏览器自动化的常用教程。

那一篇讲的是"怎么用"。

这一篇讲的是"被发现了怎么办"。

使用 Selenium / Playwright 等工具做浏览器自动化时，目标网站可能会检测到你不是真人操作。

这是很正常的现象。

理解检测机制，不是为了绕过它。

而是为了：

1
2
3
4

知道自己的自动化行为在对方眼里是什么样子。
在检测触发时合规地暂停、截图、进入人工复核。
设计不被误判的自动化行为。
构建可观测、可审计的采集系统。

本文整理常见的 WebDriver 检测机制、学习路径和合规应对代码。

边界声明：

本文只用于理解检测原理、自查自动化行为、合规诊断和防御性工程。不提供绕过检测、规避风控、伪造指纹或批量规避反爬的代码。

一、为什么会有 WebDriver 检测？

网站做检测，原因通常包括：

1
2
3
4
5

保护服务可用性：自动化请求可能占用大量资源。
保护数据权益：大规模自动化采集可能违反使用条款。
防止欺诈：自动化可能用于刷单、刷票、抢购。
保护用户体验：恶意爬虫可能影响正常用户访问。
合规要求：某些行业有数据保护和访问限制义务。

从网站视角看，检测自动化行为是合理的防御手段。

从采集方视角看，理解这些检测是必要的工程知识。

但不等于"理解了就要绕过"。

更好的思路是：

1

理解检测 → 调整策略 → 降低频率 → 授权访问 → 合规采集。

而不是：

1

理解检测 → 绕过检测 → 加大并发 → 突破限制。

网络检测：检查请求特征和协议指纹。
环境检测：检查运行环境的完整性。

def check_webdriver_flag(driver) -> bool:
    """检查当前会话是否暴露了 webdriver 标志"""
    value = driver.execute_script("return navigator.webdriver")
    if value:
        log_event(
            event="webdriver_flag_detected",
            detail="navigator.webdriver is true",
            url=driver.current_url,
        )
    return bool(value)

def scan_all_injected_variables(driver) -> dict:
    """扫描所有注入变量并记录版本信息"""
    result = driver.execute_script("""
    const injected = {};
    const prefixes = ['cdc_', '__webdriver', '__selenium', '__fxdriver',
                       '__driver', '__nightmare', '__phantomas',
                       '__call_function', '__browser'];
    for (const prefix of prefixes) {
        const matches = Object.keys(window).filter(k => k.startsWith(prefix));
        if (matches.length) injected[prefix] = matches;
    }
    return injected;
    """)

    chrome_version = driver.capabilities.get("browserVersion", "unknown")
    driver_version = driver.capabilities.get("chrome", {}).get("chromedriverVersion", "unknown")

    if result:
        log_event(
            event="cdp_injected_variables",
            variables=result,
            chrome_version=chrome_version,
            chromedriver_version=driver_version,
        )

    return result

建议做法：

  • 每次升级 Chrome 或 ChromeDriver 后运行一次扫描。
  • 将结果记录到审计日志，用于判断数据源是否可能检测到新的自动化特征。
  • 不要依赖"知道变量名"来删除或修改它们。

function getAudioFingerprint() {
  return new Promise((resolve) => {
    const ctx = new (window.AudioContext || window.webkitAudioContext)();
    const oscillator = ctx.createOscillator();
    oscillator.type = "triangle";
    oscillator.frequency.value = 10000;

    const compressor = ctx.createDynamicsCompressor();
    compressor.threshold.value = -50;
    compressor.knee.value = 40;
    compressor.ratio.value = 12;
    compressor.attack.value = 0;
    compressor.release.value = 0.25;

    oscillator.connect(compressor);
    compressor.connect(ctx.destination);
    oscillator.start(0);

    const analyser = ctx.createAnalyser();
    oscillator.connect(analyser);
    const dataArray = new Float32Array(analyser.frequencyBinCount);

    setTimeout(() => {
      analyser.getFloatTimeDomainData(dataArray);
      const hash = Array.from(dataArray.slice(0, 30))
        .map((v) => v.toFixed(6))
        .join(",");
      oscillator.stop();
      ctx.close();
      resolve(hash);
    }, 100);
  });
}

  let straightCount = 0;
  for (let i = 2; i < positions.length; i++) {
    const dx1 = positions[i-1].x - positions[i-2].x;
    const dy1 = positions[i-1].y - positions[i-2].y;

class BehaviorLogger:
    """记录自动化操作行为，用于自查"""

    def __init__(self):
        self.actions = []

    def log_action(self, action_type: str, detail: str = ""):
        self.actions.append({
            "type": action_type,
            "time": time.time(),
            "detail": detail,
        })

    def get_intervals(self) -> list[float]:
        """获取操作间隔列表"""
        if len(self.actions) < 2:
            return []
        return [
            self.actions[i]["time"] - self.actions[i-1]["time"]
            for i in range(1, len(self.actions))
        ]

    def analyze_uniformity(self) -> dict:
        """分析操作间隔均匀性"""
        intervals = self.get_intervals()
        if len(intervals) < 3:
            return {"status": "insufficient_data"}

        avg = sum(intervals) / len(intervals)
        variance = sum((x - avg) ** 2 for x in intervals) / len(intervals)

        return {
            "avg_interval": round(avg, 3),
            "variance": round(variance, 3),
            "count": len(intervals),
            "uniform": variance < 0.5,
        }

from datetime import datetime, timedelta


class RequestMonitor:
    """监控请求频率和模式，用于自查"""

    def __init__(self):
        self.requests = []

    def log_request(self, url: str, method: str = "GET"):
        self.requests.append({
            "url": url,
            "method": method,
            "time": datetime.now(),
        })

    def check_frequency(self, window_seconds: int = 60, threshold: int = 30) -> dict:
        """检查时间窗口内的请求频率"""
        now = datetime.now()
        cutoff = now - timedelta(seconds=window_seconds)
        recent = [r for r in self.requests if r["time"] >= cutoff]

        domain_counts = Counter()
        for r in recent:
            from urllib.parse import urlparse
            domain = urlparse(r["url"]).netloc
            domain_counts[domain] += 1

        high_frequency = {
            d: c for d, c in domain_counts.items() if c > threshold
        }

        return {
            "window_seconds": window_seconds,
            "total_requests": len(recent),
            "high_frequency_domains": high_frequency,
        }

      maxTouchPoints: navigator.maxTouchPoints,
      hover: window.matchMedia('(hover: hover)').matches,
      pointer_coarse: window.matchMedia('(pointer: coarse)').matches,
    };
    """)
    results.append(DetectionCheckResult(
        check_type="touch_pointer",
        detected=False,
        details=touch,
    ))

    # 8. WebRTC 可用性
    webrtc = driver.execute_script(
        "return typeof RTCPeerConnection !== 'undefined'"
    )
    results.append(DetectionCheckResult(
        check_type="webrtc",
        detected=False,
        details={"available": webrtc},
        risks=["webrtc_available"] if webrtc else [],
    ))

    # 9. Service Worker
    sw = driver.execute_script("""
    if (!navigator.serviceWorker) return { supported: false };
    return {
      supported: true,
      controller: !!navigator.serviceWorker.controller,
    };
    """)
    results.append(DetectionCheckResult(
        check_type="service_worker",
        detected=sw.get("controller", False),
        details=sw,
        risks=["sw_controller_active"] if sw.get("controller") else [],
    ))

    return results

from enum import Enum


class DetectionAction(str, Enum):
    CONTINUE = "continue"
    PAUSE = "pause"
    MANUAL_REVIEW = "manual_review"
    STOP = "stop"


def handle_detection_result(
    results: list[DetectionCheckResult],
    source_config: dict,
) -> DetectionAction:
    """根据检测结果和数据源配置决定动作"""

    all_risks = []
    for r in results:
        all_risks.extend(r.risks)

    if not all_risks:
        log_event(event="detection_clean", risks=[])
        return DetectionAction.CONTINUE

    # 记录所有检测风险
    log_event(
        event="detection_risks_found",
        risks=all_risks,
        url=source_config.get("url"),
    )

    # 检查数据源是否明确允许自动化
    if source_config.get("automation_allowed") is True:
        log_event(
            event="automation_allowed_by_config",
            risks=all_risks,
        )
        return DetectionAction.CONTINUE

    # 有风险且未明确允许，进入人工复核
    return DetectionAction.MANUAL_REVIEW


def execute_detection_action(
    action: DetectionAction,
    driver,
    source_config: dict,
    results: list[DetectionCheckResult],
) -> dict:
    """执行检测后的动作"""

    if action == DetectionAction.CONTINUE:
        return {"status": "continued", "action": "continue"}

    if action == DetectionAction.MANUAL_REVIEW:
        screenshot_path = take_screenshot(driver, "detection_review")
        review_id = create_review_case(
            reason="webdriver_detection",
            risks=[r.risks for r in results if r.detected],
            screenshot=screenshot_path,
            url=driver.current_url,
            source_id=source_config.get("source_id"),
        )
        return {
            "status": "manual_review",
            "review_id": review_id,
            "screenshot": screenshot_path,
        }

    if action == DetectionAction.PAUSE:
        log_event(event="task_paused", reason="detection")
        return {"status": "paused"}

    if action == DetectionAction.STOP:
        log_event(event="task_stopped", reason="detection")
        return {"status": "stopped"}

    return {"status": "unknown"}

十七、常见误区

1. “装了反检测插件就安全了”

反检测插件可能有遗漏，而且会随着浏览器更新失效。

2. “修改 navigator.webdriver 就够了”

行为检测、TLS 指纹、请求频率等都不依赖 navigator.webdriver。

3. “检测到就一定要绕过”

更好的做法是调整策略、降低频率、走授权接口。

4. “Headless 模式一定能被检测”

新 Headless 模式（--headless=new）已经改进了很多特征。

5. “检测代码只有安全研究员会写”

检测逻辑对网站开发者来说并不复杂，很多是几行代码的事。

6. “我的自动化没人管”

大规模自动化可能影响网站服务，即使不绕过检测也可能违反使用条款。

7. “关闭了 navigator.webdriver 就万事大吉”

Canvas 指纹、AudioContext 指纹、字体枚举、TLS 指纹等完全独立于 navigator.webdriver。单独关闭 webdriver 标志不能解决所有检测问题。

8. “Canvas 指纹只有高安全站点才用”

Canvas 指纹已经是很多反爬/WAF 服务的标准能力，不是"高级技巧"。任何使用 Canvas 来做渲染的检测方都可以顺便加入指纹逻辑。

9. “服务器 IP 能完全隐藏我的位置”

WebRTC 可以绕过代理泄露真实 IP，时区和语言设置也会暴露地理位置信息。单靠代理 IP 不能完全隐藏位置。

10. “无头模式 + UA 修改 = 无人能发现”

即使 UA 和窗口尺寸都正常，Canvas/AudioContext/字体/WebGL 等指纹在 Headless 环境下仍与真实桌面环境有显著差异。

class DetectionAwareCrawler:
    """带检测意识的采集器"""

    def __init__(self, driver, source_config: dict):
        self.driver = driver
        self.source_config = source_config
        self.behavior_logger = BehaviorLogger()
        self.request_monitor = RequestMonitor()

    def crawl(self, url: str) -> dict:
        self.driver.get(url)
        self.behavior_logger.log_action("page_load", url)
        self.request_monitor.log_request(url)

        try:
            return self.driver.find_element(By.TAG_NAME, "body").text
        except Exception:

十九、面试表达

如果面试官问：

1

WebDriver 检测有哪些常见方式？

可以这样回答：

常见的检测方式包括：navigator.webdriver 属性检测、ChromeDriver 注入变量检测（如 cdc_ 前缀）、浏览器指纹异常检测（Headless 标识、窗口尺寸、插件数量、WebGL/Canvas/AudioContext 指纹、字体枚举）、硬件与地区交叉校验（CPU核数、内存、时区、语言）、行为模式分析（鼠标轨迹、点击间隔、输入速度）、Touch/指针类型检测、TLS 指纹差异、WebRTC IP 泄露、Service Worker 持久化跟踪等。每一类都有独立的检测逻辑，单独处理一种无法解决整体问题。

如果问：

1

自动化被检测到了怎么办？

可以这样回答：

我会在采集系统中内建检测自查机制，每次操作前检查 navigator.webdriver、CDP 注入特征和浏览器指纹。如果检测到风险且数据源不允许自动化，就暂停任务、截图保存证据、进入人工复核。不会尝试绕过检测，而是调整策略、降低频率或走授权接口。

如果问：

1

如何让自动化行为更自然？

可以这样回答：

我会在操作之间加入随机延迟，避免完全均匀的点击间隔和输入速度。但这样做的目的是降低对目标服务的影响，而不是欺骗行为分析系统。如果目标站点明确不允许自动化，即使操作再自然也不应该继续。

如果问：

1

Headless 模式有什么检测风险？

可以这样回答：

旧版 Headless 模式 User-Agent 包含 HeadlessChrome、窗口 outerWidth/outerHeight 为 0、可能没有插件和 WebGL 支持。Chrome 112+ 的新 Headless 模式改善了这些问题，但 Canvas 指纹、AudioContext 指纹、字体枚举、navigator.webdriver 等仍可能暴露自动化环境。我的建议是优先使用有头模式配合虚拟显示器，运行完整的检测自查（不只查 webdriver），并根据检测结果决定是否继续。

如果问：

1

检测到自动化后应该怎么处理？

可以这样回答：

我设计了检测自查 → 风险评估 → 动作决策的流程。检测结果记录到日志，风险详情写入指标。如果数据源配置允许自动化，记录后继续；如果不允许或不确定，暂停任务、截图、创建人工复核单。所有决策都写审计日志。核心原则是：检测到风险不等于要绕过，而是要合规处理。

二十、总结

本文整理了 WebDriver 检测机制和合规应对方法。

核心结论包括：

  • 检测机制包括属性检测、行为检测、网络检测、环境检测和高级指纹检测五个维度。
  • navigator.webdriver 是最直接的检测点，Selenium 和 Playwright 默认都会设置为 true。
  • CDP 注入特征（如 cdc_ 前缀变量）是 ChromeDriver 特有的检测点，变量名随版本变化需要跟踪。
  • 浏览器指纹异常包括 Headless 标识、窗口尺寸、插件缺失、WebGL 不支持、Canvas 指纹、AudioContext 指纹、字体枚举差异等。
  • 硬件信息（CPU 核数、内存大小）、时区、语言和 IP 地理位置的交叉校验是更强的检测手段。
  • Touch 支持、指针类型、权限状态等特征可以区分桌面自动化和移动端模拟。
  • WebRTC 可能绕过代理泄露真实 IP，是位置伪装检测的重要手段。
  • Service Worker 可以跨页面持久化跟踪访问行为，清理 Cookie 对其无效。
  • 行为检测分析鼠标轨迹、点击间隔、输入速度和页面停留时间。
  • TLS 指纹差异可以区分浏览器请求和 Python 库请求。
  • 学习检测机制应从标准文档、开源项目、本地实验和版本对比入手。
  • 检测到自动化后，合规处理流程是：记录 → 判断 → 暂停或复核 → 审计日志。
  • 不应该用修改参数、注入脚本等方式绕过检测。
  • 检测自查应该内建到采集系统中，作为可观测性的一部分。
  • 数据源配置应明确是否允许自动化，检测结果应进入人工复核闭环。
  • Chrome 新 Headless 模式（--headless=new）改善了部分指纹特征，但 navigator.webdriver 仍然暴露。
  • 采集系统的合规策略不依赖"规避检测"，而是依赖"检测到就暂停并复核"。

到这里，我们补齐了 WebDriver 检测机制的认知。

加上第 37 篇的 Selenium 教程和第 38 篇的 Frida 教程，浏览器自动化和移动端调试的"怎么做"和"被发现了怎么办"都覆盖了。

但系列主线不变：

我们学习检测机制，不是为了突破规则，而是为了在检测触发时做出合规的、可审计的、可追溯的工程决策。
