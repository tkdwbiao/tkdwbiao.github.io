从凑零钱到拼单词：深度拆解排列背包下的『单词拆分』

2026-03-28 18:00
阅读时长: 4 分钟

在 LeetCode 139. 单词拆分 中，我们面临一个挑战：给定一个字符串 s 和一个词典 wordDict，判断 s 是否可以由词典中的单词拼接而成。

阿彪在思考这道题时，产生了一个非常硬核的类比：这难道不就是“凑零钱”吗？

1. 阿彪的思维模型：20块钱的启示

想象你要凑齐 20 块钱，手里有面值为【2, 5, 10】的硬币：

  • 总金额：20（对应字符串 s 的总长度）。
  • 硬币面值：2, 5, 10（对应每个单词的长度）。

如果我们只看长度，这题就是问：用这些面值能不能拼出 20？ 但字符串比硬币复杂的地方在于：硬币没有长相，而单词有。

所以，我们的任务变成了：在凑齐长度的同时，每一块“面值”上的花纹（字符）必须和目标图纸（字符串 s）严丝合缝。

2. 为什么是“排列背包”？

在字符串拼接中，顺序是致命的：

  • apple + pen = applepen （正确 ✅）
  • pen + apple = penapple （错误 ❌）

为了处理这种**顺序敏感（Permutation）**的问题，根据阿彪之前的“背包顺序法则”：

“求排列，必须先遍历背包容量，再遍历物品。”

这样在每一个长度位置 i，我们都会尝试所有单词作为“最后一块拼图”的可能性。

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> bool:
        n = len(s)
        # 1. dp[i] 代表：长度为 i 的子串（s[0:i]）能不能拼出来
        dp = [False] * (n + 1)
        
        # 2. 初始状态：长度为 0 的空字符串默认可以拼成（地基）
        dp[0] = True
        
        # 3. 外层遍历背包容量（即字符串长度 i）
        for i in range(1, n + 1):
            # 4. 内层遍历物品（即每一个单词）
            for word in wordDict:
                w_len = len(word)
                
                # 5. 核心判定逻辑（阿彪的拼图理论）：
                #   - 剩下的长度够放这个单词吗？ (i >= w_len)
                #   - 这个单词之前的路是通的吗？ (dp[i - w_len])
                #   - 这个单词的花纹对得上图纸吗？ (s[i-w_len : i] == word)
                if i >= w_len and dp[i - w_len] and s[i - w_len : i] == word:
                    dp[i] = True
                    # 只要找到一种拼法能通，长度 i 就成了，直接看下一个长度
                    break 
                    
        return dp[n]

4. 阿彪的进阶总结：从“生成”到“剪枝”

在学习初期，阿彪曾想过：“我能不能先把所有长度等于 N 的排列全部造出来，最后看 s 在不在里面？”

深度反思：

  • 盲目生成：如果不看图纸（不比对字符），我们会生成数以亿计的无用组合（比如 s 开头是 a，我们却生成了一堆 b 开头的），内存会瞬间爆炸。
  • 实时比对：代码中的 s[i-w_len : i] == word 就像是一个实时过滤器。它并没有破坏“生成所有排列”的逻辑，而是把那些“注定失败”的排列在出生前就剪掉了。

结论：动态规划的本质，就是带有记忆且只走正确道路的全排列。

5. 极致优化：按“需求长度”主动出击

阿彪发现，字典里的单词虽然多，但它们的长度种类其实很少。与其被动比对每个单词，不如主动寻找“我需要的长度”。

优化核心：

  1. 哈希提速：将 wordDict 转为 set，使单词查找耗时从 $O(M)$ 降至 $O(1)$。
  2. 长度剪枝：预处理出字典中所有单词的唯一长度并排序。

class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> bool:
        # 优化1：哈希表，找单词 O(1)
        word_set = set(wordDict) 
        # 优化2：只记录字典里出现过的唯一长度，并排序
        word_lens = sorted(list(set(len(w) for w in wordDict)))
        
        n = len(s)
        dp = [False] * (n + 1)
        dp[0] = True
        
        for i in range(1, n + 1):
            for l in word_lens: # 只尝试真正存在的长度
                if l > i: 
                    break # 长度超了，后续更长的也不用看了
                
                # 核心逻辑：如果减去这个长度后的前驱是通的，且切片在 set 里
                if dp[i - l] and s[i - l : i] in word_set:
                    dp[i] = True
                    break
        return dp[n]

6. 复杂度深度对比

维度基础版本极致优化版
时间复杂度$O(N \cdot M \cdot L)$$O(N \cdot K \cdot L)$
空间复杂度$O(N)$$O(N + M)$
性能关键取决于单词总数 $M$取决于长度种类 $K$

注：$N$ 为字符串长度，$L$ 为平均单词长度，$K$ 为唯一长度个数。

7. 阿彪的“面试话术”补丁 [抱拳]

如果面试官追问优化原理，阿彪建议这样回答：

“我的优化思路是 ‘由被动匹配转为主动索取’。

原始解法受限于字典规模（$M$），而优化解法受限于长度种类数（$K$）。在实际场景中，$K$ 往往远小于 $M$。

配合 Set 的常数级查找 和 有序长度的提前断路（break），我将无效的字符串比对次数降到了最低。这体现了对‘剪枝’思想的深度应用。”
