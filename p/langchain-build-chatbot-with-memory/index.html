LangChain 实战：构建一个支持多轮对话的聊天机器人

2025-09-17 10:00
阅读时长: 15 分钟

上一篇文章里，我们系统讲了 LangChain 的 Memory 机制。

核心结论是：大模型 API 本身通常是无状态的，所谓“记忆”，本质上是应用层保存历史消息，并在下一次调用时把历史上下文重新传给模型。

这一篇，我们不再只讲概念，而是把 Prompt、Model、Parser、Runnable 和 Memory 串起来，构建一个真正支持多轮上下文的聊天机器人。

它不是一个复杂产品，但已经具备真实聊天应用的核心骨架。

一、前言

到目前为止，我们已经学过：

  • 如何调用 Chat Model。
  • 如何用 ChatPromptTemplate 管理提示词。
  • 如何用 LCEL 编排 prompt | model | parser。
  • 如何用 Output Parser 整理模型输出。
  • 如何理解 Runnable 的统一调用接口。
  • 如何用 RunnableWithMessageHistory 管理历史消息。

这些知识点如果分开看，像是一个个 API。

但真实项目里，它们不是孤立存在的，而是组合成一条完整链路。

一个最小聊天机器人至少需要：

如果再进一步，它还需要：

  • 命令行交互循环
  • 不同 session 的历史隔离
  • 清空历史
  • 流式输出
  • 错误处理
  • 历史长度控制
  • 后续接入 RAG 或 Agent 的扩展点

本文会从最小版本开始，一步一步实现。

最终你会得到一个可以在命令行运行的多轮聊天机器人。

二、我们要构建什么？

本文目标是实现一个 LangChain 聊天机器人，具备下面这些能力。

1. 支持多轮上下文

用户可以这样连续提问：

1
2
3
4
5

你：我想学习 LangChain，应该从哪里开始？
AI：可以先从 Model、Prompt、LCEL、Runnable 和 Memory 开始。

你：那第二个是什么？
AI：第二个是 Prompt，它负责把用户任务组织成模型能理解的消息结构。

第二轮中的“第二个”，模型能理解是因为它看到了上一轮历史。

2. 支持命令行交互

我们会做一个最简单的 CLI：

1
2
3
4
5

你：你好
AI：你好，我是你的 LangChain 学习助手。

你：exit
已退出。

这样方便本地练习和调试。

3. 支持会话 ID

不同会话要有不同历史。

例如：

1
2

session_id = "study-langchain"
session_id = "write-blog"

两个会话互不影响。

4. 支持清空历史

用户可以输入：

1

/clear

清空当前会话历史。

5. 支持流式输出

聊天应用如果等模型完整生成后再显示，体验会比较差。

所以我们会加入流式输出版本：

1

AI：这 是 一 段 逐 步 输 出 的 回 答...

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.messages import HumanMessage, AIMessage

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名专业、耐心、清晰的 LangChain 学习助手。请使用中文回答。"),
    MessagesPlaceholder("chat_history"),
    ("human", "{question}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.5,
)

chain = prompt | model | StrOutputParser()

chat_history = []

question1 = "我想学习 LangChain，应该从哪里开始？"
answer1 = chain.invoke({
    "chat_history": chat_history,
    "question": question1,
})
print("AI:", answer1)

chat_history.append(HumanMessage(content=question1))
chat_history.append(AIMessage(content=answer1))

question2 = "那它和直接调用模型 API 有什么区别？"
answer2 = chain.invoke({
    "chat_history": chat_history,
    "question": question2,
})
print("AI:", answer2)

这里的关键是：

1

MessagesPlaceholder("chat_history")

它让历史消息可以插入到 Prompt 中。

但这仍然是手动维护历史。

每次调用后都要写：

1
2

chat_history.append(HumanMessage(content=question))
chat_history.append(AIMessage(content=answer))

这适合理解原理，但不适合长期使用。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", """
你是一名专业、耐心、清晰的 LangChain 学习助手。
请使用中文回答。
面向有 Python 基础但刚接触大模型应用的开发者。
必要时给出简短代码示例。
"""),
    MessagesPlaceholder("chat_history"),
    ("human", "{question}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.5,
)

chain = prompt | model | StrOutputParser()

histories = {}


def get_session_history(session_id: str):
    if session_id not in histories:
        histories[session_id] = InMemoryChatMessageHistory()
    return histories[session_id]


chatbot = RunnableWithMessageHistory(
    chain,
    get_session_history,
    input_messages_key="question",
    history_messages_key="chat_history",
)

config = {"configurable": {"session_id": "demo-session"}}

answer1 = chatbot.invoke(
    {"question": "我想学习 LangChain，应该从哪里开始？"},
    config=config,
)
print("AI:", answer1)

answer2 = chatbot.invoke(
    {"question": "那它和直接调用模型 API 有什么区别？"},
    config=config,
)
print("AI:", answer2)

1. histories 是什么？

1

histories = {}

这是一个内存字典，用来保存不同 session 的历史。

它的结构可以理解成：

1
2
3
4

{
    "demo-session": InMemoryChatMessageHistory(...),
    "another-session": InMemoryChatMessageHistory(...),
}

2. get_session_history 是什么？

1
2
3
4

def get_session_history(session_id: str):
    if session_id not in histories:
        histories[session_id] = InMemoryChatMessageHistory()
    return histories[session_id]

RunnableWithMessageHistory 会通过这个函数拿到当前 session 的历史。

如果历史不存在，就创建一份新的。

3. input_messages_key 是什么？

1

input_messages_key="question"

因为我们调用时传入的是：

1

{"question": "..."}

所以要告诉 LangChain：当前用户输入字段叫 question。

4. history_messages_key 是什么？

1

history_messages_key="chat_history"

因为 Prompt 中的占位符是：

1

MessagesPlaceholder("chat_history")

所以这里也要写 chat_history。

5. session_id 是什么？

1

config = {"configurable": {"session_id": "demo-session"}}

它表示当前调用属于哪个会话。

同一个 session_id 会共享历史。

不同 session_id 会使用不同历史。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", """
你是一名专业、耐心、清晰的 LangChain 学习助手。
请使用中文回答。
面向有 Python 基础但刚接触大模型应用的开发者。
回答要结构清晰，不要编造不存在的 API。
如果不确定，请说明不确定。
"""),
    MessagesPlaceholder("chat_history"),
    ("human", "{question}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.5,
)

chain = prompt | model | StrOutputParser()

histories = {}


def get_session_history(session_id: str):
    if session_id not in histories:
        histories[session_id] = InMemoryChatMessageHistory()
    return histories[session_id]


chatbot = RunnableWithMessageHistory(
    chain,
    get_session_history,
    input_messages_key="question",
    history_messages_key="chat_history",
)


def ask(question: str, session_id: str) -> str:
    return chatbot.invoke(
        {"question": question},
        config={"configurable": {"session_id": session_id}},
    )


def clear_history(session_id: str):
    histories[session_id] = InMemoryChatMessageHistory()


def main():
    session_id = input("请输入 session_id，直接回车使用默认会话：").strip() or "default"

    print("\nLangChain 多轮聊天机器人已启动。")
    print("输入 exit 或 quit 退出，输入 /clear 清空当前会话历史。\n")

    while True:
        question = input("你：").strip()

        if not question:
            continue

        if question.lower() in {"exit", "quit"}:
            print("已退出。")
            break

        if question == "/clear":
            clear_history(session_id)
            print("当前会话历史已清空。")
            continue

        try:
            answer = ask(question, session_id)
            print("AI：", answer)
        except Exception as e:
            print("调用失败：", e)


if __name__ == "__main__":
    main()

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", """
你是一名专业、耐心、清晰的 LangChain 学习助手。
请使用中文回答。
回答要适合有 Python 基础但刚接触大模型应用的开发者。
"""),
    MessagesPlaceholder("chat_history"),
    ("human", "{question}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.5,
)

chain = prompt | model | StrOutputParser()

histories = {}


def get_session_history(session_id: str):
    if session_id not in histories:
        histories[session_id] = InMemoryChatMessageHistory()
    return histories[session_id]


chatbot = RunnableWithMessageHistory(
    chain,
    get_session_history,
    input_messages_key="question",
    history_messages_key="chat_history",
)


def stream_answer(question: str, session_id: str):
    chunks = []

    for chunk in chatbot.stream(
        {"question": question},
        config={"configurable": {"session_id": session_id}},
    ):
        print(chunk, end="", flush=True)
        chunks.append(chunk)

    print()
    return "".join(chunks)


def main():
    session_id = input("请输入 session_id，直接回车使用默认会话：").strip() or "default"

    print("\nLangChain 流式聊天机器人已启动。")
    print("输入 exit 或 quit 退出。\n")

    while True:
        question = input("你：").strip()

        if not question:
            continue

        if question.lower() in {"exit", "quit"}:
            print("已退出。")
            break

        print("AI：", end="", flush=True)

        try:
            stream_answer(question, session_id)
        except Exception as e:
            print("\n调用失败：", e)


if __name__ == "__main__":
    main()

这里使用：

1
2

for chunk in chatbot.stream(...):
    print(chunk, end="", flush=True)

如果模型服务支持流式输出，你就可以看到内容逐步打印。

流式输出和历史写入

使用 RunnableWithMessageHistory 时，流式调用也需要保证最终回答能写入历史。

通常 LangChain 会在 runnable 调用完成后把本轮输入输出写入历史。

如果你自己手写流式逻辑，就要注意：

  • 一边打印 chunk。
  • 一边累积完整回答。
  • 结束后把完整回答写入历史。

使用封装好的 RunnableWithMessageHistory 能减少这类重复代码。

十、控制历史长度

当前 demo 用的是内存历史，而且没有限制长度。

如果用户一直聊，历史会越来越长。

这会带来几个问题：

  • token 成本越来越高。
  • 响应越来越慢。
  • 可能超过上下文窗口。
  • 旧信息可能干扰新问题。

最简单的控制方式是只保留最近若干条消息。

1. 简单裁剪函数

1
2
3
4
5

def trim_history(session_id: str, max_messages: int = 20):
    history = get_session_history(session_id)

    if len(history.messages) > max_messages:
        history.messages = history.messages[-max_messages:]

可以在每次调用后执行：

1
2

answer = ask(question, session_id)
trim_history(session_id)

注意：不同 ChatMessageHistory 实现是否允许直接修改 messages，要看具体类。内存版本通常适合 demo，生产环境应使用更清晰的存储接口。

2. 为什么不是越多越好？

多轮对话里，历史不是越完整越好。

例如用户前 20 轮都在聊 Python 虚拟环境，后面突然开始聊 LangChain Agent。

如果旧历史全部带上，可能会干扰模型判断当前主题。

更好的策略是：

  • 最近几轮完整保留。
  • 更早历史生成摘要。
  • 用户长期偏好单独保存。
  • 无关闲聊不进入长期记忆。

3. 下一阶段可以加入摘要记忆

比如当消息超过 20 条时，调用模型生成摘要：

1

当前对话摘要：用户正在学习 LangChain，已经了解 Prompt、LCEL、Runnable 和 Memory，现在想构建多轮聊天机器人。

然后 Prompt 变成：

这样可以兼顾长期上下文和 token 成本。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", """
你是一名专业、耐心、清晰的 LangChain 学习助手。
请使用中文回答。
面向有 Python 基础但刚接触大模型应用的开发者。
回答要结构清晰，必要时给出简短代码示例。
如果不确定，请说明不确定，不要编造不存在的 API。
"""),
    MessagesPlaceholder("chat_history"),
    ("human", "{question}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.5,
)

chain = (prompt | model | StrOutputParser()).with_config({
    "run_name": "langchain_memory_chatbot",
    "tags": ["langchain", "chatbot", "memory"],
})

histories = {}


def get_session_history(session_id: str):
    if session_id not in histories:
        histories[session_id] = InMemoryChatMessageHistory()
    return histories[session_id]


chatbot = RunnableWithMessageHistory(
    chain,
    get_session_history,
    input_messages_key="question",
    history_messages_key="chat_history",
)


def ask(question: str, session_id: str) -> str:
    return chatbot.invoke(
        {"question": question},
        config={"configurable": {"session_id": session_id}},
    )


def clear_history(session_id: str):
    histories[session_id] = InMemoryChatMessageHistory()


def show_history(session_id: str):
    history = get_session_history(session_id)

    if not history.messages:
        print("当前会话没有历史消息。")
        return

    for message in history.messages:
        role = message.type
        print(f"{role}: {message.content}")


def main():
    session_id = input("请输入 session_id，直接回车使用默认会话：").strip() or "default"

    print("\nLangChain 多轮聊天机器人已启动。")
    print("命令：exit/quit 退出，/clear 清空历史，/history 查看历史。\n")

    while True:
        question = input("你：").strip()

        if not question:
            continue

        if question.lower() in {"exit", "quit"}:
            print("已退出。")
            break

        if question == "/clear":
            clear_history(session_id)
            print("当前会话历史已清空。")
            continue

        if question == "/history":
            show_history(session_id)
            continue

        try:
            answer = ask(question, session_id)
            print("AI：", answer)
        except Exception as e:
            print("调用失败：", e)


if __name__ == "__main__":
    main()

十三、常见问题

1. 为什么我的机器人还是不记得上文？

优先检查四件事：

  1. Prompt 里是否有 MessagesPlaceholder("chat_history")。
  2. RunnableWithMessageHistory 是否设置了 history_messages_key="chat_history"。
  3. 调用时是否传了 config={"configurable": {"session_id": "..."}}。
  4. 每次调用是否使用了同一个 session_id。

少任何一项，都可能导致历史没有正确注入。

2. 为什么不同用户串话？

通常是 session 管理有问题。

比如所有用户都用了：

1

session_id = "default"

真实应用必须给不同用户、不同对话分配不同 session_id 或 conversation_id。

3. InMemoryChatMessageHistory 能用于生产吗？

不建议。

它适合 demo 和本地测试。

生产环境应该把历史放到 Redis、数据库或其他可靠存储中。

否则程序重启后历史会丢失，多进程部署时历史也会不一致。

4. 聊天历史会不会无限增长？

如果不控制，会。

所以必须设计：

  • 最大消息数
  • 最大 token 数
  • 过期时间
  • 摘要压缩
  • 清空会话

否则成本和延迟都会越来越高。

5. RunnableWithMessageHistory 和 ConversationChain 怎么选？

如果你在旧教程里看到 ConversationChain，要注意版本差异。

在现代 LCEL / Runnable 写法中，更推荐使用 RunnableWithMessageHistory。

它和 prompt | model | parser 这套组合方式更一致。

6. 多轮聊天机器人是不是 Agent？

不是。

多轮聊天机器人只是能记住上下文。

Agent 还需要具备：

  • 判断是否调用工具
  • 选择工具
  • 组织工具参数
  • 读取工具结果
  • 多步推理和行动循环

后续 Agent 篇会专门展开。

十四、最佳实践

1. 从 CLI 开始，不要一上来做复杂 Web 应用

命令行版本更容易调试。

先确认：

  • Prompt 正常
  • 模型调用正常
  • 历史注入正常
  • session 隔离正常

再接入 Web API 和前端。

2. Prompt 中明确角色和边界

聊天机器人尤其需要清晰 system message。

例如：

1
2
3

你是一名 LangChain 学习助手。
请使用中文回答。
如果不确定，请说明不确定，不要编造不存在的 API。

这不能解决所有问题，但能明显改善输出稳定性。

3. session_id 必须由后端可信生成

不要完全相信前端传来的 session_id。

后端应该校验：

  • 当前用户是否有权访问这个会话
  • conversation_id 是否属于当前用户
  • 是否允许继续写入历史

4. 历史存储要可清理

聊天历史不是越多越好。

至少要支持：

  • 用户主动删除
  • 会话过期
  • 管理端清理
  • 敏感信息过滤

5. 尽早考虑流式输出

聊天产品如果没有流式输出，体验会差很多。

即使后端先做同步版本，也要在设计上预留 streaming 能力。

6. 给链路加 run_name 和 tags

推荐：

1
2
3
4

chain = chain.with_config({
    "run_name": "chatbot_chain",
    "tags": ["chatbot", "memory"],
})

后续接入 LangSmith 或其他观测系统时，会更容易排查问题。
