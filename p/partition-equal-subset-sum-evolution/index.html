动态规划进阶：从‘数钱’到‘打勾’，深度拆解分割等和子集

2026-04-01 17:07
阅读时长: 3 分钟

在 [LeetCode 416. 分割等和子集] 中，我们要判断一个数组能否分成和相等的两部分。 这道题是 0/1 背包问题的终极变身。今天阿彪带大家走一遍从“基础建模”到“极致压缩”的进化之路。

一、 核心思想：建模的艺术

这道题表面上是分割数组，实则是在玩凑金额游戏：

  1. 求目标：先算出数组总和 sum。如果 sum 是奇数，直接返回 False。
  2. 定目标：我们要找的是：能不能从数组里挑出几个数，让它们的和正好等于 target = sum // 2。
  3. 套模型：
    • 背包容量：target。
    • 物品：数组里的每个数字。
    • 0/1 特性：每个数字只能用一次。

二、 阶段一：价值法（最符合直觉的模拟）

1. 思想 (Idea)

把数字既看作“重量”也看作“价值”。我有一个容量为 target 的口袋，我尽量往里装东西。如果最后我发现我装进去的最大总重量，刚好等于口袋容量，那我不就凑齐了吗？

2. 过程 (Process)

  • dp[i][j] 存的是：前 i 个物品在容量 j 下能装下的最大重量。
  • 决策：max(不拿, 拿了要腾地方 + 加上当前数值)。
  • 注意：数组长度要开到 target + 1，循环要踩到 target。

class Solution:
    def canPartition(self, nums: List[int]) -> bool:
        total = sum(nums)
        if total % 2 == 1: return False
        target = total // 2
        n = len(nums)
        
        # dp[i][j] 存储当前能凑出的最大重量
        dp = [[0] * (target + 1) for _ in range(n + 1)]
        
        for i in range(1, n + 1):
            cur_num = nums[i-1]
            for j in range(1, target + 1):
                if j < cur_num:
                    dp[i][j] = dp[i-1][j]
                else:
                    # 核心：max 决策，看最后能不能顶到 target
                    dp[i][j] = max(dp[i-1][j], dp[i-1][j - cur_num] + cur_num)
                    
        return dp[n][target] == target

三、 阶段二：布尔法（逻辑纯粹化）

1. 思想 (Idea)

既然我们只关心“能不能凑齐”，不关心具体多重，为什么不直接存 True/False 呢？

2. 过程 (Process)

  • dp[i][j] 存的是：前 i 个数能否正好凑出和为 j。
  • 初始化：dp[i][0] = True（凑出 0 元永远是可以的，即什么都不选）。
  • 决策：不选 or 选（看剩下的缺口能不能凑出）。

class Solution:
    def canPartition(self, nums: List[int]) -> bool:
        # ... 前期判断同上 ...
        dp = [[False] * (target + 1) for _ in range(n + 1)]
        for i in range(n + 1): dp[i][0] = True # 地基
            
        for i in range(1, n + 1):
            cur_num = nums[i-1]
            for j in range(1, target + 1):
                if j < cur_num:
                    dp[i][j] = dp[i-1][j]
                else:
                    # 只要有一种情况行，我这格就是 True
                    dp[i][j] = dp[i-1][j] or dp[i-1][j - cur_num]
        return dp[n][target]

四、 阶段三：一维优化（空间降维打击）🌟

1. 思想 (Idea)

观察发现，每一行只参考上一行。我们能不能只用一根线（一行数组）来更新？

“核心：必须倒序遍历！为了防止这一轮刚更新的数据污染了后面的计算。”

2. 过程 (Process)

  • 只开辟 target + 1 长度的数组。
  • 内层循环从 target 倒退到 cur_num。
  • 原理：当你更新 dp[j] 时，左边的 dp[j - cur_num] 还是上一轮的老数据，保证了物品只被使用一次。

class Solution:
    def canPartition(self, nums: List[int]) -> bool:
        total = sum(nums)
        if total % 2 != 0: return False
        target = total // 2
        
        # 极致压缩：一维滚动数组
        dp = [False] * (target + 1)
        dp[0] = True
        
        for cur_num in nums:
            # 关键：由后向前遍历，避免重复使用物品
            for j in range(target, cur_num - 1, -1):
                dp[j] = dp[j] or dp[j - cur_num]
            
            # 提前剪枝：如果目标已达成，直接收工
            if dp[target]: return True
            
        return dp[target]

五 : 阿彪的总结与深度反思 [抱拳]

1. 关于“消失的最后一列”

在写 2D DP 时，阿彪曾踩坑：数组开了 target 长度。 反思：数组下标从 0 开始。想存 target 的状态，长度必须是 target + 1。

2. 关于“倒序”的物理意义

  • 正序：像是在货架上边走边拿，拿了一块还能拿一块 $\to$ 完全背包。
  • 倒序：像是背对着货架拿，拿完一个就往前走，绝不回头看刚才拿的位置 $\to$ 0/1 背包。

3. 时空复杂度

  • 时间：$O(N \cdot M)$，其中 $N$ 是物品数，$M$ 是 $sum/2$。
  • 空间：从 $O(N \cdot M)$ 优化到 $O(M)$。
