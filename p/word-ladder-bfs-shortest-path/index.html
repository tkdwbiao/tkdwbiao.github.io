算法精髓：为什么‘求最短’必须锁死 BFS？

2026-04-04 14:48
阅读时长: 2 分钟

在 110. 字符串迁移 中，我们要找从一个单词变到另一个单词的最短路径。阿彪在实践中发现，很多同学（包括我）容易把 BFS 写成 DFS。今天我们就来拆解这其中的差别。

一、 核心思想：波纹扩散

想象你往平静的湖中心扔了一块石头：

  • BFS（广度优先）：水波是一圈一圈均匀向外扩散的。第一圈碰到岸边的水纹，一定是路程最短的。
  • DFS（深度优先）：像一只无头苍蝇，选准一个方向就飞到底，撞了南墙才回头。它找到的第一条路，可能绕了整整一圈。

“求最少、最短、最优，BFS 是唯一真神。”

二、 解题方法：队列 + 状态剪枝

  1. 双端队列 (Deque)：使用 popleft() 确保我们是按“步数”从小到大进行搜索。
  2. 按位转换：对于单词的每一位，尝试替换为 a-z。这比遍历整个词典去比对要快得多（尤其是词典很大时）。
  3. 即时销毁：为了防止反复访问同一个单词导致死循环，一旦一个单词入队，我们就把它从词典中 remove 掉。

三、 举例说明：hit -> cog

词典：["hot","dot","dog","lot","log","cog"]

  1. 第一层：hit (步数1)
    • 变换：hot。在词典中，入队。词典剩 ["dot","dog","lot","log","cog"]。
  2. 第二层：hot (步数2)
    • 变换：dot, lot。入队。
  3. 第三层：dot (步数3)
    • 变换：dog。入队。
  4. 第四层：dog (步数4)
    • 变换：cog。命中目标！ 返回步数 5。

四、 阿彪的避坑与反思 [抱拳]

1. pop() 的陷阱

在 Python 的 deque 中：

  • pop() 是弹出右边（DFS）。
  • popleft() 才是弹出左边（BFS）。 一字之差，复杂度天差地别。

2. 步数传递

建议直接在队列里存元组 (word, steps)。这样每个节点都自带“档案”，不需要去维护一个复杂的全局距离表，代码更简洁。

3. 时间复杂度

$O(M^2 \times N)$。其中 $M$ 是单词长度，$N$ 是词典规模。

  • 遍历 $M$ 个位置，每个位置换 26 次。
  • 字符串切片拼接是 $O(M)$。

五、 同类思想题推荐

掌握了 BFS 求最短路径，你可以横扫以下题目：

  1. [LeetCode 102. 二叉树的层序遍历]：BFS 的基础形态。
