最长递增子序列：从 O(n²) 填表到 O(nlogn) 扑克分堆的华丽转身

2026-03-28 21:00
阅读时长: 2 分钟

在上一篇博客中，我们用 $O(n^2)$ 的动态规划解决了 LeetCode 300. 最长递增子序列。但当数据量达到 10 万级时，$O(n^2)$ 的“货比三家”法就会超时。

今天阿彪带大家用 “贪心 + 二分” 实现降维打击，将复杂度优化至极致的 $O(n \log n)$。

1. 核心哲学：扑克牌分堆（Patience Sorting）

想象你在玩一种扑克游戏，目标是把牌分成尽可能少的堆：

  1. 规则：每张新牌必须压在“第一个比它大”的堆顶上。
  2. 新建堆：如果当前的牌比所有堆顶都大，就在右边新建一堆。

为什么这个堆数就是答案？

这个算法的精髓在于贪心：我们每次都把一个较小的数替换掉较大的堆顶，是为了压低每一堆的高度，从而给后面还没来的数字留出更大的增长空间。

2. 为什么这里能用二分？

在分堆的过程中，我们维护一个数组 tails，它存储了每个堆最顶上的那张牌。

阿彪发现了一个惊人的事实：tails 数组永远是严格递增的！

  • 因为新开堆的牌一定比左边所有的牌都大。
  • 而替换操作是用一个更小的数去替换一个较大的堆顶，不会破坏递增性。

既然 tails 是有序的，那么“寻找该把牌压在哪个堆”的过程，就可以用 bisect_left 瞬间完成！

import bisect

class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        if not nums: return 0
        
        # tails[i] 表示长度为 i+1 的所有递增子序列中，最小的结尾数值
        tails = []
        
        for num in nums:
            # 1. 在有序的 tails 中，用二分查找定位第一个 >= num 的位置
            # 这就是我们要找的“最合适的堆”
            idx = bisect.bisect_left(tails, num)
            
            # 2. 如果索引等于长度，说明 num 比所有堆顶都大
            if idx == len(tails):
                tails.append(num) # 新建一堆
            else:
                # 3. 否则，用 num 替换掉原有的堆顶（贪心优化，增加潜力）
                tails[idx] = num
        
        # 最终堆的数量（即 tails 的长度）就是最长递增子序列的长度
        return len(tails)

4. 阿彪的细节复盘：为什么是 bisect_left？

如果数组里有重复数字，比如 [1, 3, 3, 5]，新来一个 3：

  • 我们题目要求的是“严格递增”，所以新来的 3 不能接在原本的 3 后面。
  • 它应该去替换掉第一个 3。
  • bisect_left 刚好能帮我们定位到第一个 3 的位置。

阿彪小结 [抱拳]： 从 $O(n^2)$ 到 $O(n \log n)$，我们不仅改变了代码，更改变了观察问题的维度——从“寻找结尾”上升到了“维护潜力”。
