LangChain 实战：从零构建一个 RAG 知识库问答系统

2025-09-29 10:00
阅读时长: 15 分钟

前面几篇文章里，我们已经分别讲了 RAG 的核心组件：

1

3

Document Loader
  ↓
Text Splitter
  ↓
Embedding
  ↓
Vector Store
  ↓
Retriever

如果只看单个组件，理解起来还不算难。

但真正做项目时，问题会变成：如何把这些组件串起来，做成一个可以运行、可以调试、可以逐步扩展的知识库问答系统？

这一篇我们就从零实现一个最小但完整的 RAG 应用。

一、前言

很多人学习 RAG 时，会分别学到这些代码：

1
2
3
4

loader.load()
splitter.split_documents(docs)
Chroma.from_documents(...)
retriever.invoke(question)

每一段单独看都能理解。

但真正写应用时，经常会卡在这些问题上：

  • 文档应该放在哪里？
  • 向量库是每次启动都重新构建吗？
  • 构建索引和在线问答要不要拆开？
  • Prompt 里上下文应该怎么组织？
  • 如果检索不到资料，模型应该怎么回答？
  • 如何打印检索结果做调试？
  • 如何把来源一起展示给用户？

这些问题不解决，RAG 就容易停留在 demo。

本文会实现一个本地 Markdown 知识库问答系统，覆盖完整流程：

  1. 准备项目结构。
  2. 准备依赖和环境变量。
  3. 编写知识库文档。
  4. 加载并切分文档。
  5. 构建 Chroma 向量库。
  6. 加载 Retriever。
  7. 设计 RAG Prompt。
  8. 实现问答链。
  9. 返回答案和来源。
  10. 增加调试函数。
  11. 处理知识库没有答案的情况。
  12. 总结常见问题和优化方向。

LangChain 是一个用于构建大模型应用的开发框架。

# RAG

RAG 是 Retrieval-Augmented Generation，也就是检索增强生成。

它的基本流程是：先根据用户问题从知识库中检索相关资料，再把资料放入 Prompt，最后让模型基于资料生成回答。

RAG 适合解决大模型缺少私有知识、最新知识和可追溯来源的问题。

RAG 的关键不只是模型回答，还包括文档加载、文档切分、Embedding、向量库、Retriever 和 Prompt 约束。

这些文档很小，但足够演示完整流程。

import os
from dotenv import load_dotenv
from langchain_community.document_loaders import DirectoryLoader, TextLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

load_dotenv()

DOCS_DIR = "data/docs"
PERSIST_DIR = "data/chroma_db"


def load_documents():
    loader = DirectoryLoader(
        DOCS_DIR,
        glob="**/*.md",
        loader_cls=TextLoader,
        loader_kwargs={"encoding": "utf-8"},
    )

    docs = loader.load()

    for doc in docs:
        doc.metadata["kb_name"] = "langchain-demo"
        doc.metadata["language"] = "zh-cn"

    return docs


def split_documents(docs):
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=600,
        chunk_overlap=100,
        separators=["\n\n", "\n", "。", "！", "？", "；", "，", " ", ""],
    )

    return splitter.split_documents(docs)


def create_embeddings():
    return OpenAIEmbeddings(
        model=os.getenv("EMBEDDING_MODEL", "text-embedding-3-small"),
        api_key=os.getenv("OPENAI_API_KEY"),
        base_url=os.getenv("OPENAI_BASE_URL") or None,
    )


def build_index():
    docs = load_documents()
    print("原始文档数量：", len(docs))

    chunks = split_documents(docs)
    print("切分后 chunk 数量：", len(chunks))

    embeddings = create_embeddings()

    Chroma.from_documents(
        documents=chunks,
        embedding=embeddings,
        persist_directory=PERSIST_DIR,
    )

    print("向量索引构建完成：", PERSIST_DIR)


if __name__ == "__main__":
    build_index()

import os
from dotenv import load_dotenv
from langchain_chroma import Chroma
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

load_dotenv()

PERSIST_DIR = "data/chroma_db"


def create_embeddings():
    return OpenAIEmbeddings(
        model=os.getenv("EMBEDDING_MODEL", "text-embedding-3-small"),
        api_key=os.getenv("OPENAI_API_KEY"),
        base_url=os.getenv("OPENAI_BASE_URL") or None,
    )


def load_vectorstore():
    embeddings = create_embeddings()

    return Chroma(
        persist_directory=PERSIST_DIR,
        embedding_function=embeddings,
    )


def format_docs(docs):
    return "\n\n".join(
        f"来源：{doc.metadata.get('source', 'unknown')}\n{doc.page_content}"
        for doc in docs
    )


vectorstore = load_vectorstore()
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

prompt = ChatPromptTemplate.from_messages([
    ("system", """
你是一名严谨的知识库问答助手。
请只根据上下文回答问题。
如果上下文没有答案，请回答：根据已提供资料无法确定。
回答时尽量简洁、准确。
"""),
    ("human", """
上下文：
{context}

问题：{question}
"""),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.2,
)

rag_chain = (
    {
        "context": retriever | format_docs,
        "question": RunnablePassthrough(),
    }
    | prompt
    | model
    | StrOutputParser()
)


if __name__ == "__main__":
    question = input("请输入问题：")
    answer = rag_chain.invoke(question)
    print("\n回答：")
    print(answer)

1. 用户问题进入链路

例如：

1

输入是一个字符串。

2. Retriever 检索相关文档

1

这表示：

  1. 把用户问题交给 retriever。
  2. retriever 返回 Document 列表。
  3. format_docs 把列表格式化成字符串。

3. RunnablePassthrough 保留原问题

1

"question": RunnablePassthrough()

它把原始用户问题原样传给 Prompt。

最终 Prompt 得到两个变量：

1
2

context：检索出来的上下文

4. Prompt 约束模型

1
2

如果上下文没有答案，请回答：根据已提供资料无法确定。

这很重要。

RAG 不是把资料塞给模型就结束了，还要明确告诉模型如何使用资料。

5. Output Parser 返回字符串

1

| StrOutputParser()

它把模型消息转换成普通字符串，方便打印或返回给 API。

def answer_with_sources(question: str):
    docs = retriever.invoke(question)
    context = format_docs(docs)

    answer = (prompt | model | StrOutputParser()).invoke({
        "context": context,
        "question": question,
    })

    sources = []
    for doc in docs:
        source = doc.metadata.get("source", "unknown")
        if source not in sources:
            sources.append(source)

    return answer, sources

    print("检索结果数量：", len(docs))

  • Embedding 模型是否适合中文。
  • k 是否太小。
  • 文档内容是否太少。
  • metadata filter 是否过滤错了。

十三、处理没有答案的问题

相似度检索有一个特点：

即使知识库没有答案，它也可能返回最相似的几条结果。

例如用户问：

1

今天北京天气怎么样？

知识库只有 LangChain、LCEL、RAG，但向量库仍然可能返回一条文档。

这时只靠普通 similarity 检索不够稳。

可以使用 similarity_score_threshold：

1
2
3
4
5
6
7

retriever = vectorstore.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={
        "k": 3,
        "score_threshold": 0.7,
    },
)

但要注意：

  • 不同向量库分数含义不同。
  • 阈值需要用真实问题测试。
  • 不要直接照搬 0.7。

如果检索结果为空，可以直接返回：

 1
 2
 3
 4

def answer_with_sources(question: str):
    docs = retriever.invoke(question)

    if not docs:
        return "根据已提供资料无法确定。", []

    context = format_docs(docs)

    answer = (prompt | model | StrOutputParser()).invoke({
        "context": context,
        "question": question,

    sources = []
    for doc in docs:
        source = doc.metadata.get("source", "unknown")
        if source not in sources:
            sources.append(source)

    return answer, sources

这样可以减少模型在无关上下文里硬编答案。

import os
from dotenv import load_dotenv
from langchain_chroma import Chroma
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

PERSIST_DIR = "data/chroma_db"


def create_embeddings():
    return OpenAIEmbeddings(
        model=os.getenv("EMBEDDING_MODEL", "text-embedding-3-small"),
        api_key=os.getenv("OPENAI_API_KEY"),
        base_url=os.getenv("OPENAI_BASE_URL") or None,
    )


def load_vectorstore():
    embeddings = create_embeddings()

    return Chroma(
        persist_directory=PERSIST_DIR,
        embedding_function=embeddings,
    )


def format_docs(docs):
    return "\n\n".join(
        f"来源：{doc.metadata.get('source', 'unknown')}\n{doc.page_content}"
        for doc in docs
    )


def unique_sources(docs):
    sources = []

    for doc in docs:
        source = doc.metadata.get("source", "unknown")
        if source not in sources:
            sources.append(source)

    return sources


vectorstore = load_vectorstore()

retriever = vectorstore.as_retriever(
    search_kwargs={"k": 3}
)

prompt = ChatPromptTemplate.from_messages([
    ("system", """
你是一名严谨的知识库问答助手。
请只根据上下文回答问题。
如果上下文没有答案，请回答：根据已提供资料无法确定。
回答时尽量简洁、准确。
"""),
    ("human", """
上下文：
{context}

问题：{question}
"""),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.2,
)

answer_chain = prompt | model | StrOutputParser()


def answer_with_sources(question: str):
    docs = retriever.invoke(question)

    if not docs:
        return "根据已提供资料无法确定。", []

    context = format_docs(docs)

    answer = answer_chain.invoke({
        "context": context,
        "question": question,
    })

    return answer, unique_sources(docs)


def debug_retrieval(question: str):
    docs = retriever.invoke(question)

    print("问题：", question)
    print("检索结果数量：", len(docs))

    for index, doc in enumerate(docs, start=1):
        print("=" * 60)
        print("排名：", index)
        print("metadata：", doc.metadata)
        print(doc.page_content[:500])


if __name__ == "__main__":
    while True:
        question = input("\n请输入问题，输入 exit 退出：")

        if question.lower() in {"exit", "quit"}:
            break

        if question.startswith("/debug "):
            debug_retrieval(question.replace("/debug ", "", 1))
            continue

        answer, sources = answer_with_sources(question)

        print("\n回答：")
        print(answer)

        if sources:
            print("\n来源：")
            for source in sources:
                print("-", source)

十五、为什么要拆成 build_index.py 和 ask.py？

这是工程化 RAG 的一个基本习惯。

1. build_index.py 是离线流程

它适合在这些时候运行：

  • 第一次导入知识库。
  • 文档更新后重新构建。
  • 定时同步知识库。
  • CI/CD 或后台任务中更新索引。

它关注的是：

1

原始文档 -> chunks -> vectors -> vector store

2. ask.py 是在线流程

它适合用户每次提问时运行。

它关注的是：

1

用户问题 -> retrieve -> prompt -> model -> answer

如果每次用户提问都重新加载、切分、embedding 全部文档，会非常慢，也非常浪费成本。

所以真实项目通常会把两者拆开。

十六、如何更新知识库？

学习阶段可以直接删除 data/chroma_db/，然后重新运行：

1

python build_index.py

但生产环境不能这么简单。

真实系统要考虑：

  • 新增文档如何入库。
  • 修改文档如何更新旧 chunk。
  • 删除文档如何从向量库删除。
  • 如何避免重复写入。
  • 如何记录文档版本。
  • 如何处理构建失败。

常见做法是在 metadata 中加入：

1
2
3
4
5
6

metadata={
    "doc_id": "stable-document-id",
    "chunk_id": "stable-chunk-id",
    "source": "data/docs/rag.md",
    "updated_at": "2025-09-29",
}

这样后续可以按 doc_id 或 chunk_id 做增量更新。

本文为了聚焦入门，先用全量重建。

RAG Prompt 不需要很花哨，但要明确。

基础版可以包含三条规则：

2
3

1. 只根据上下文回答。
2. 上下文没有答案时，说无法确定。
3. 回答简洁准确。

例如：

prompt = ChatPromptTemplate.from_messages([
    ("system", """

十八、常见问题

1. 为什么每次回答都很慢？

先确认是否每次都在重新构建向量库。

在线问答时应该加载已有向量库：

1
2
3
4

Chroma(
    persist_directory=PERSIST_DIR,
    embedding_function=embeddings,
)

而不是每次都：

1

Chroma.from_documents(...)

2. 为什么回答不基于知识库？

先用 /debug 看检索结果。

如果 Retriever 没有返回正确文档，问题在检索层。

如果 Retriever 返回了正确文档，但模型仍然乱答，问题可能在 Prompt 约束或模型设置。

3. 为什么检索不到明明存在的内容？

可能原因：

  • 文档没有被加载。
  • 文档切分后语义被切断。
  • Embedding 模型不适合当前语言。
  • 用户问法和文档表达差异太大。
  • k 太小。
  • metadata filter 过滤错了。

可以尝试：

  • 打印 chunks。
  • 增大 k。
  • 调整 chunk size 和 overlap。
  • 使用 MultiQueryRetriever。
  • 使用混合检索或 rerank。

4. 为什么知识库没有答案时还是会回答？

因为普通相似度检索总会返回最相近的几条。

解决方向：

  • 使用 similarity_score_threshold。
  • 检索结果为空时直接返回无法确定。
  • 在 Prompt 中明确资料不足时拒答。
  • 准备无答案问题做评估。

5. Chroma 适合生产吗？

Chroma 很适合学习、本地开发和小型项目。

生产环境要结合需求判断：

  • 数据规模。
  • 并发量。
  • 权限过滤。
  • 多租户。
  • 备份恢复。
  • 运维能力。

如果团队已经使用 PostgreSQL，可以考虑 PGVector。

如果需要独立向量数据库，可以评估 Milvus、Qdrant、Weaviate、Pinecone 等。

十九、最佳实践

1. 先让最小链路跑通

不要一开始就上复杂架构。

先完成：

1

Markdown -> chunks -> Chroma -> Retriever -> Prompt -> Answer

跑通后再优化。

2. 构建索引和问答服务分开

不要每次提问都重新 embedding 文档。

离线索引和在线查询要分离。

3. 保留来源 metadata

至少保留：

1
2
3
4
5
6

source
file_name
title
page
section
doc_id

没有来源的 RAG，很难建立用户信任。

4. 先调 Retriever，再调 Prompt

回答错了，先看检索结果。

如果上下文错了，Prompt 再好也只是补救。

5. 准备评估问题集

至少准备：

  • 知识库能回答的问题。
  • 同义表达的问题。
  • 多跳问题。
  • 知识库没有答案的问题。
  • 容易混淆的问题。

每次调整 chunk、Embedding、Retriever、Prompt 后都跑一遍。

6. 不要忽略权限过滤

企业知识库中，不该给用户看的文档，不能进入 Prompt。

权限必须在检索层完成，而不是靠 Prompt 约束。

1. 接入 Web API

结合前面 Memory 篇，可以让系统支持追问。

例如：

1

用户：它和微调有什么区别？

这时需要同时考虑：

  • 历史消息。
  • 当前问题改写。
  • 检索查询生成。
  • 上下文长度控制。

3. 加入 rerank

基础向量检索返回 top-k 后，可以用 reranker 再排序。

适合：

  • 文档很多。
  • top-k 噪声较多。
  • 对答案准确性要求高。

4. 加入混合检索

向量检索适合语义问题。

关键词检索适合：

  • 错误码。
  • 编号。
  • API 名称。
  • 产品型号。
  • 合同号。

真实系统经常把两者结合。

5. 接入 LangSmith

当链路变复杂后，需要观察：

  • 用户问题是什么。
  • Retriever 返回了什么。
  • Prompt 最终长什么样。
  • 模型输出是什么。
  • 每一步耗时多少。

后续我们会专门讲 LangSmith。
