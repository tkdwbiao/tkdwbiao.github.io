Frida 在这里的角色，是帮助我们观察这些层之间的调用关系。

二、Frida 的两种常用运行模式

Android 调试里，Frida 最常见的两种模式是：

1
2

attach 模式：App 已经启动，Frida 附加到正在运行的进程。
spawn 模式：Frida 先启动目标 App，并在启动早期注入脚本。

2.1 attach 模式

attach 适合 App 已经打开、你想观察某个按钮点击或某个页面行为的场景。

1

frida -U -n com.example.demo -l audit.js

含义：

参数说明
-U连接 USB 设备
-n通过进程名附加
-l加载 JavaScript 脚本

attach 的优点：

  • 使用简单。
  • 适合观察页面操作、按钮点击、请求触发。
  • 不需要重新启动 App。

attach 的局限：

  • App 启动早期逻辑可能已经执行完了。
  • 如果目标方法只在启动阶段调用，attach 后可能观察不到。
  • 某些初始化、证书加载、配置读取逻辑可能错过。

2.2 spawn 模式

spawn 适合观察 App 启动阶段逻辑，例如登录态恢复、配置加载、首次请求、证书初始化等。

1

frida -U -f com.example.demo -l audit.js

含义：

参数说明
-f启动目标 App 并注入脚本
-U连接 USB 设备
-l加载脚本

spawn 的优点：

  • 能观察启动早期逻辑。
  • 适合看首次请求、初始化配置、证书加载。
  • 适合定位“App 一打开就请求了什么”。

spawn 的注意点：

  • 有些 App 启动时依赖复杂，日志会很多。
  • 需要区分初始化噪声和真正业务逻辑。
  • 公开文章不应把 spawn 用作规避检测或绕过安全控制的入口。

2.3 选择建议

场景推荐模式
观察点击登录按钮后的方法调用attach
观察 App 启动时读取本地登录态spawn
观察首次请求前加载的配置spawn
观察某个页面的权限判断attach
排查 token 刷新逻辑attach / spawn 都可能需要
观察证书、网络配置初始化spawn 更容易看到

四、常用 Hook 脚本模板：只观察，不绕过

4.1 Hook 普通 Java 方法

Java.perform(function () {
  const UserService = Java.use('com.example.demo.UserService');

  UserService.login.overload('java.lang.String', 'java.lang.String').implementation = function (username, password) {
    console.log('[UserService.login] username = ' + username);

    const result = this.login(username, password);

    console.log('[UserService.login] result = ' + result);
    return result;
  };
});

这个脚本做了三件事：

1
2
3

打印登录入参。
调用原始方法。
打印原始返回值。

它没有修改登录结果，也没有绕过认证。

Java.perform(function () {
  const EditorImpl = Java.use('android.app.SharedPreferencesImpl$EditorImpl');

  EditorImpl.putString.overload('java.lang.String', 'java.lang.String').implementation = function (key, value) {
    console.log('[SharedPreferences.putString] ' + key + ' = ' + value);
    return this.putString(key, value);
  };

  EditorImpl.putBoolean.overload('java.lang.String', 'boolean').implementation = function (key, value) {
    console.log('[SharedPreferences.putBoolean] ' + key + ' = ' + value);
    return this.putBoolean(key, value);
  };

  EditorImpl.apply.implementation = function () {
    console.log('[SharedPreferences.apply] called');
    return this.apply();
  };

适合观察：

保存内容说明

first_launch首次启动标记

注意：不要在文章或日志里泄露真实 token、手机号、身份证、设备号等敏感信息。写审计报告时要脱敏。

Java.perform(function () {

  RequestBuilder.url.overload('java.lang.String').implementation = function (url) {

很多 App 会检测调试环境、代理环境或 Hook 工具。

检测点说明

这些检测的安全目的：

十三、常见问题

Q1：Frida 调试登录流程，是不是就是绕过登录？

不是。授权调试的目标是观察登录流程、定位错误、验证安全设计，而不是修改登录结果。公开文章和审计报告都不应提供绕过登录的脚本。

Q2：证书校验可以 Hook 吗？

在自有 App 的安全审计中，可以观察证书配置加载、初始化时机、失败日志和配置版本。但不应提供绕过证书校验或关闭证书校验的可复用代码。

Q3：为什么要关注首次请求保存的 XML？

因为很多 App 第一次启动会请求远端配置、证书版本、功能开关、实验配置，并保存到 SharedPreferences 或本地文件。观察这些写入点可以帮助判断初始化链路是否正常。

Q4：Frida 检测和代理检测是不是“坏东西”？

不是。它们通常是安全防护的一部分，用于保护账号、支付、隐私和接口安全。审计时应关注误伤、可观测性、用户提示和风险分级，而不是绕过。

Q5：面试中怎么讲 Frida？

不要说“我会 hook 绕过某某”。更好的表达是：

我会在授权环境中使用 Frida 做动态观察，结合调用栈、网络日志和本地存储，梳理登录态、权限判断、设备信息和网络请求的调用链，并把结果整理成可审计、可复现的流程图。
