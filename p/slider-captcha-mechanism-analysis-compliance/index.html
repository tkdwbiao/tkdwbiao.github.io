一、滑块验证码是什么

滑块验证码（Slider CAPTCHA）是一种基于人机交互的验证方式：

  1. 服务器生成一张背景图和一张拼图碎片。
  2. 用户需要把碎片拖动到背景图上缺口的位置。
  3. 服务器校验拖动轨迹、时间、精度等维度来判断是否为真人。

与传统的字符验证码相比，滑块验证码的优势：

  • 用户体验好——拖一下就行，不需要输入复杂字符。
  • 安全性高——可以分析鼠标轨迹、加速度、抖动等行为特征。
  • 适配移动端——触屏拖拽天然友好。

三、滑块验证码的工作原理

理解滑块验证码的工作原理，是正确应对的前提。

3.1 前端流程

1
2
3
4

1. 页面加载验证码 JS SDK
2. 前端向验证码服务请求背景图和拼图碎片
3. 用户拖动碎片
4. 前端采集拖拽轨迹（坐标序列 + 时间戳）
5. 前端将轨迹数据加密后提交到验证码服务
6. 验证码服务返回 validate token
7. 业务后端用 validate token 向验证码服务做二次校验

3.2 服务端校验维度

滑块验证码不只看"缺口位置对不对"，还会校验多个维度：

维度说明
位置精度碎片中心与缺口中心的偏移量，通常允许 ±5px
拖拽时间太快（< 300ms）或太慢（> 10s）都可能被判定为机器
轨迹形状人类拖拽有自然的加速-匀速-减速曲线，机器往往是匀速
Y轴抖动人类拖拽时鼠标不可能完美水平，会有轻微的 Y 轴波动
加速度变化人类拖拽的加速度是渐变的，机器往往是阶跃的
回弹与修正人类拖拽可能有轻微的回弹再修正，这是人类特征
设备指纹浏览器指纹、Canvas 指纹、WebGL 指纹等

四、Selenium 滑块操作详解

在自有系统或授权测试环境中，可以用 Selenium 的 ActionChains 模拟鼠标按下、移动、暂停和释放。这里重点不是“突破验证码”，而是掌握浏览器自动化中鼠标动作的常用接口。

from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.common.action_chains import ActionChains
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC


driver = webdriver.Chrome()
driver.get("https://your-test-site.example/login")

wait = WebDriverWait(driver, 10)
slider = wait.until(
    EC.element_to_be_clickable((By.CSS_SELECTOR, ".slider-btn"))
)

ActionChains(driver) \
    .click_and_hold(slider) \
    .move_by_offset(200, 0) \
    .release() \
    .perform()

这个写法的特点：

  • click_and_hold(slider)：移动到滑块元素并按住。
  • move_by_offset(200, 0)：从当前鼠标位置向右移动 200 像素。
  • release()：释放鼠标。
  • perform()：执行整条动作链。

它适合说明 API，不适合真实滑块验证，因为轨迹过于机械。

def convert_gap_to_drag_distance(
    gap_x_on_image: int,
    image_natural_width: int,
    image_display_width: int,
    slider_initial_offset: int = 0,
) -> int:
    scale = image_display_width / image_natural_width
    return round(gap_x_on_image * scale - slider_initial_offset)

4.6 分段轨迹：匀速、加速、减速

def drag_by_steps(driver, slider, steps: list[tuple[int, int, float]]) -> None:
    actions = ActionChains(driver)
    actions.click_and_hold(slider).perform()

    for x_offset, y_offset, pause_seconds in steps:
        ActionChains(driver) \
            .move_by_offset(x_offset, y_offset) \
            .pause(pause_seconds) \
            .perform()

    ActionChains(driver).release().perform()

import random


def generate_acceleration_track(distance: int) -> list[tuple[int, int, float]]:
    """生成先加速后减速的拖动轨迹。"""
    if distance <= 0:
        return []

    track = []
    current = 0.0
    velocity = 0.0
    interval = 0.02
    mid = distance * random.uniform(0.55, 0.7)

    while current < distance:
        if current < mid:
            acceleration = random.uniform(2.0, 4.0)
        else:
            acceleration = -random.uniform(3.0, 5.0)

        move = velocity * interval + 0.5 * acceleration * (interval ** 2) * 100
        velocity = max(velocity + acceleration * interval * 10, 0.8)
        move = max(move, 1.0)

        remaining = distance - current
        if move > remaining:
            move = remaining

        current += move
        x_offset = round(move)
        y_offset = random.choice([-1, 0, 0, 0, 1])
        pause_seconds = random.uniform(0.01, 0.04)
        track.append((x_offset, y_offset, pause_seconds))

    diff = distance - sum(step[0] for step in track)
    if diff:
        track.append((diff, 0, random.uniform(0.03, 0.08)))

    return track

def add_end_correction(
    track: list[tuple[int, int, float]],
    overshoot: int = 3,
) -> list[tuple[int, int, float]]:
    if overshoot <= 0:
        return track

    return [
        *track,
        (overshoot, random.choice([-1, 0, 1]), random.uniform(0.05, 0.12)),
        (-overshoot, 0, random.uniform(0.05, 0.12)),
    ]


track = generate_acceleration_track(180)
track = add_end_correction(track, overshoot=3)
drag_by_steps(driver, slider, track)

注意：终点修正不是“万能通过技巧”，只是鼠标动作模拟中的一个概念。真实验证码会综合分析轨迹、设备、会话、风险评分、验证参数等因素。

4.10 常见问题

  • element not interactable：元素存在但不可见，改用 visibility_of_element_located 或 element_to_be_clickable。
  • move target out of bounds：移动距离超过窗口或轨道范围，检查浏览器窗口大小和轨道宽度。
  • stale element reference：页面刷新或验证码重载后，旧元素引用失效，需要重新定位。
  • iframe 内找不到元素：先确认是否已经切换到正确 iframe。
  • 拖动后无响应：可能是没有按住正确的滑块按钮，也可能是页面监听的是 Pointer Events / Touch Events，而不是普通 Mouse Events。

  • 上述代码仅用于自有系统测试或授权场景。
  • move_by_offset 是相对偏移，不是绝对坐标。
  • 分段拖动时，每一段都可以单独 .perform()，便于调试。
  • 截图坐标和 DOM 坐标可能受 devicePixelRatio 影响。

import cv2
import numpy as np


def detect_gap_by_template(bg_path: str, slider_path: str) -> int:
    """用模板匹配检测缺口 x 坐标"""
    bg = cv2.imread(bg_path)
    slider = cv2.imread(slider_path)

    # 转灰度
    bg_gray = cv2.cvtColor(bg, cv2.COLOR_BGR2GRAY)
    slider_gray = cv2.cvtColor(slider, cv2.COLOR_BGR2GRAY)

    # 边缘检测增强
    bg_edge = cv2.Canny(bg_gray, 100, 200)
    slider_edge = cv2.Canny(slider_gray, 100, 200)

    # 模板匹配
    result = cv2.matchTemplate(bg_edge, slider_edge, cv2.TM_CCOEFF_NORMED)
    _, max_val, _, max_loc = cv2.minMaxLoc(result)

    # max_loc[0] 就是缺口的 x 坐标
    gap_x = max_loc[0]
    print(f"缺口位置: x={gap_x}, 匹配置信度: {max_val:.4f}")

    return gap_x

def detect_gap_by_contour(bg_path: str) -> int:
    """用轮廓检测从背景图上找缺口"""
    bg = cv2.imread(bg_path)
    bg_gray = cv2.cvtColor(bg, cv2.COLOR_BGR2GRAY)

    # 高斯模糊去噪
    blurred = cv2.GaussianBlur(bg_gray, (5, 5), 0)

    # Canny 边缘检测
    edges = cv2.Canny(blurred, 50, 150)

    # 膨胀操作让轮廓更连续
    kernel = np.ones((3, 3), np.uint8)
    edges = cv2.dilate(edges, kernel, iterations=1)

    # 查找轮廓
    contours, _ = cv2.findContours(edges, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

    # 筛选：缺口轮廓通常有特定的面积和宽高比
    for contour in contours:
        x, y, w, h = cv2.boundingRect(contour)
        area = cv2.contourArea(contour)
        # 缺口大约 50-70px 宽，40-60px 高
        if 50 < w < 70 and 40 < h < 60 and area > 1500:
            print(f"检测到缺口: x={x}, y={y}, w={w}, h={h}, area={area}")
            return x

    return -1

5.3 模板匹配的局限

  • 背景图复杂时，匹配准确率会下降。
  • 拼图碎片形状各异（圆角、锯齿），通用性有限。
  • 部分验证码会对图像做干扰处理（模糊、噪点、偏移）。
  • 这些方法适合学习和实验，不适合直接用于大规模自动化。

import requests
import time

API_KEY = "your_api_key"


def solve_geetest_v3(
    site_url: str,
    gt: str,
    challenge: str
) -> str:
    """通过 2Captcha 解决 GeeTest v3 验证码"""
    # 提交任务
    response = requests.post("https://2captcha.com/in.php", data={
        "key": API_KEY,
        "method": "geetest",
        "api_server": "api.geetest.com",
        "gt": gt,
        "challenge": challenge,
        "pageurl": site_url,
        "json": 1
    })
    task_id = response.json().get("request")

    if not task_id:
        raise Exception(f"提交任务失败: {response.json()}")

    # 轮询结果
    for _ in range(60):
        time.sleep(5)
        result = requests.get("https://2captcha.com/res.php", params={
            "key": API_KEY,
            "action": "get",
            "id": task_id,
            "json": 1
        })
        data = result.json()
        if data.get("status") == 1:
            return data["request"]
        if data.get("request") != "CAPCHA_NOT_READY":
            raise Exception(f"识别失败: {data}")

    raise Exception("超时")

八、滑块验证码的合规边界

这是最重要的一节。

8.1 什么能做

  • 在自有系统上测试和优化滑块验证码的体验。
  • 在授权范围内使用合规的验证码识别服务。
  • 学习和理解滑块验证码的工作原理和技术实现。
  • 训练模型用于自有产品的验证码优化和安全性测试。
  • 接入打码平台处理自有业务的验证码。

8.2 什么不该做

  • 不编写自动绕过他人网站滑块验证码的脚本。
  • 不批量自动通过第三方网站的验证码。
  • 不把训练好的模型用于未授权的采集场景。
  • 不逆向破解验证码的加密算法来伪造验证结果。
  • 不把打码平台用于未授权的批量注册、爬取等行为。

8.3 遇到滑块验证码时的正确做法

在数据采集过程中遇到滑块验证码时：

1
2
3
4
5
6

1. 暂停任务，降低采集频率。
2. 检查是否有合法的 API 或数据源可以替代采集。
3. 检查采集行为是否在目标网站的授权范围内。
4. 如果是自有系统的验证码，可以联系运维获取测试白名单。
5. 如果必须处理，考虑接入合规的打码平台。
6. 记录验证码出现的上下文，用于后续分析采集策略。

九、面试常见问题

Q1：滑块验证码的检测维度有哪些？

核心维度：位置精度、拖拽时间、轨迹形状（加速-匀速-减速曲线）、Y 轴抖动、加速度变化、回弹与修正、设备指纹。单独一个维度不能判断是否为机器人，通常是多个维度综合评分。

Q2：模板匹配检测缺口有什么局限？

模板匹配在背景简单时效果好，但背景图复杂时误检率高；拼图碎片形状各异，通用模板难以适配；部分验证码会对图像加干扰（模糊、偏移、噪点）；不同厂商的图像处理方式不同，需要针对性调整。

Q3：打码平台的原理是什么？

分两类：人工平台（2Captcha、Anti-Captcha）把验证码任务分发给真人操作员解决；AI 平台（CapSolver、CapMonster Cloud）用训练好的深度学习模型自动识别。人工平台准确率高但速度慢、成本高；AI 平台速度快、成本低，但部分复杂类型准确率不如人工。

Q4：训练 YOLO 模型检测滑块缺口需要多少数据？

建议至少 500-1000 张标注图片。数据量太少容易过拟合，太多标注成本高。关键在于数据质量——覆盖不同背景、不同缺口形状、不同光照条件。可以使用数据增强（翻转、色调变化、缩放）来扩充数据集。

Q5：如何降低被滑块验证码拦截的概率？

根本方法是降低采集频率、使用合理的 User-Agent、模拟正常用户行为模式、检查授权范围。技术手段只是辅助，合规才是核心。
