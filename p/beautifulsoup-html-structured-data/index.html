大模型时代的数据采集工程 05：BeautifulSoup 网页解析实战

阅读时长: 14 分钟

前面几篇文章里，我们已经完成了爬虫采集链路的前半段：

1

3

理解 HTTP / HTTPS 与 TCP/IP。
用 Requests 构建稳定请求客户端。
理解 Cookie、Session、Token 和登录态管理。

到这里，我们已经能够相对稳定地拿到响应内容。

但拿到 HTML 还不等于拿到数据。

真实网页里，数据通常藏在：

1
2

4
5
6
7

标签文本里。
标签属性里。
列表结构里。
表格里。
meta 信息里。
script 中的 JSON 片段里。
正文段落里。

所以从这一篇开始，我们进入爬虫的第二个核心能力：

1

网页解析与结构化抽取。

这一篇先讲 BeautifulSoup。

目标不是背 API，而是理解：

如何把一段 HTML 解析成稳定、可校验、可入库的结构化数据。

一、前言

很多初学者会把爬虫理解成：

1

请求网页 -> 正则匹配 -> 保存结果

但真实项目里，这样很容易出问题。

因为 HTML 不是普通字符串。

它有层级结构：

1
2
3
4
5

<article class="post">
  <h1>文章标题</h1>
  <span class="author">阿彪</span>
  <time datetime="2025-12-19">2025-12-19</time>
</article>

如果你用普通字符串查找，很快会遇到：

1
2
3
4
5
6

换行变化。
空格变化。
属性顺序变化。
标签嵌套变化。
页面多了一层 div。
文本里混入多余空白。

BeautifulSoup 的作用是：

1

把 HTML 字符串解析成一个可遍历、可搜索、可提取的文档对象。

这样你就可以围绕标签、属性、文本和结构来提取数据。

这也是后续 XPath、CSS Selector、正则、数据清洗和 LLM Schema 化抽取的基础。

二、BeautifulSoup 适合解决什么问题？

BeautifulSoup 很适合处理：

1
2
3
4
5

结构相对清晰的 HTML 页面。
新闻、博客、文档类页面。
列表页和详情页字段提取。
标签文本和属性提取。
不太严格但可被容错解析的 HTML。

它的优点是：

  • API 直观。
  • 容错能力强。
  • 适合教学和快速开发。
  • 支持 CSS Selector。
  • 对不规范 HTML 比较友好。

但它不是万能的。

不适合只靠 BeautifulSoup 解决的问题包括：

1
2
3
4
5

页面内容由 JavaScript 动态渲染。
数据实际来自接口 JSON。
需要处理复杂 XPath 轴关系。
需要极高性能解析海量页面。
需要执行浏览器环境里的脚本。

工程判断很重要。

如果页面 HTML 中已经包含目标数据，BeautifulSoup 很合适。

如果 HTML 只是一个空壳，真正数据来自接口，那应该优先找接口。

如果页面必须执行 JS 才能渲染，再考虑 Selenium 或 Playwright。

from bs4 import BeautifulSoup

html = """
<html>
  <body>
    <article class="post">
      <h1>大模型时代的数据采集工程</h1>
      <span class="author">阿彪</span>
      <time datetime="2025-12-19">2025年12月19日</time>
    </article>
  </body>
</html>
"""

soup = BeautifulSoup(html, "lxml")

title = soup.find("h1").get_text(strip=True)
author = soup.find("span", class_="author").get_text(strip=True)
publish_date = soup.find("time")["datetime"]

print(title)
print(author)
print(publish_date)

四、解析器怎么选？

创建 BeautifulSoup 对象时，需要指定解析器。

常见选择：

解析器写法特点
Python 内置html.parser无需额外安装，速度一般
lxmllxml速度快，容错好，工程中常用
html5libhtml5lib更接近浏览器解析，速度较慢

推荐：

1

如果不想安装额外依赖，也可以用：

1

爬虫工程里，解析器选择会影响：

1
2
3
4

解析速度。
容错行为。
标签树结构。
异常 HTML 的修复方式。

所以如果线上解析结果和本地不一致，要检查解析器是否一致。

from dataclasses import dataclass
from urllib.parse import urljoin
from bs4 import BeautifulSoup


@dataclass
class ArticleItem:
    title: str
    url: str
    author: str | None
    publish_date: str | None
    summary: str | None


def parse_article_list(html: str, base_url: str) -> list[ArticleItem]:
    soup = BeautifulSoup(html, "lxml")
    items = []

    for card in soup.select(".article-card"):
        title_tag = card.select_one("a.title")
        if not title_tag:
            continue

        author_tag = card.select_one(".author")
        time_tag = card.select_one("time")
        summary_tag = card.select_one(".summary")

        item = ArticleItem(
            title=title_tag.get_text(" ", strip=True),
            url=urljoin(base_url, title_tag.get("href", "")),
            author=author_tag.get_text(strip=True) if author_tag else None,
            publish_date=time_tag.get("datetime") if time_tag else None,
            summary=summary_tag.get_text(" ", strip=True) if summary_tag else None,
        )
        items.append(item)

    return items

解析逻辑可测试。
后续可以接校验、清洗和入库。

这比到处写零散变量更稳。

十二、缺失字段和异常 HTML 怎么办？

真实网页经常不稳定。

可能出现：

所以解析代码不能太脆。

错误写法：

4
5

    return tag.get_text(" ", strip=True) if tag else None

也可以对必填字段做明确判断：

1

不要为了“程序不报错”把所有异常都吞掉。

因为字段缺失可能意味着页面结构变了。

这时需要记录日志或触发告警。

from bs4 import BeautifulSoup

html = """
<table class="info">
  <tr><th>名称</th><td>示例项目</td></tr>
  <tr><th>语言</th><td>Python</td></tr>
  <tr><th>状态</th><td>运行中</td></tr>
</table>
"""

soup = BeautifulSoup(html, "lxml")

data = {}
for row in soup.select("table.info tr"):
    key_tag = row.find("th")
    value_tag = row.find("td")
    if not key_tag or not value_tag:
        continue

    key = key_tag.get_text(" ", strip=True)
    value = value_tag.get_text(" ", strip=True)
    data[key] = value

print(data)

from dataclasses import dataclass
from urllib.parse import urljoin

import requests
from bs4 import BeautifulSoup


@dataclass
class ArticleItem:
    title: str
    url: str
    summary: str | None


def fetch_html(url: str) -> str:
    response = requests.get(
        url,
        headers={"User-Agent": "bs4-demo/1.0"},
        timeout=(3, 10),
    )
    response.raise_for_status()
    return response.text


def parse_articles(html: str, base_url: str) -> list[ArticleItem]:
    soup = BeautifulSoup(html, "lxml")
    items = []

    for card in soup.select(".article-card"):
        title_tag = card.select_one("a.title")
        if not title_tag:
            continue

        summary_tag = card.select_one(".summary")
        items.append(
            ArticleItem(
                title=title_tag.get_text(" ", strip=True),
                url=urljoin(base_url, title_tag.get("href", "")),
                summary=summary_tag.get_text(" ", strip=True) if summary_tag else None,
            )
        )

    return items


url = "https://example.com/articles"
html = fetch_html(url)
articles = parse_articles(html, url)

for article in articles:
    print(article)

这段代码的结构是：

1
2
3

fetch_html：只负责请求。
parse_articles：只负责解析。
ArticleItem：定义结果结构。

这比把请求、解析、打印、保存全部写在一个函数里更容易维护。

十八、BeautifulSoup 常见坑

1. 直接链式调用导致 NoneType 错误

错误写法：

1

title = soup.select_one(".title").get_text(strip=True)

如果 .title 不存在，就会报错。

更稳的写法：

1
2

title_tag = soup.select_one(".title")
title = title_tag.get_text(strip=True) if title_tag else None

2. 全局选择器太宽

例如：

1

links = soup.select("a")

这会拿到导航、页脚、推荐位等所有链接。

应该先限定容器：

1

links = soup.select(".article-list .article-card a.title")

3. 忽略相对 URL

提取出来 /post/1 后直接保存，后续请求可能失败。

应该用：

1

urljoin(base_url, href)

4. 忽略编码问题

Requests 会根据响应头和内容猜测编码。

如果页面乱码，要检查：

1
2

print(response.encoding)
print(response.apparent_encoding)

必要时可以设置：

1

response.encoding = response.apparent_encoding

但更重要的是确认服务端返回的 Content-Type 和 charset。

5. 把解析失败当成请求失败

请求成功只是拿到了页面。

解析失败是另一层问题。

日志和状态里应该分开记录。

例如：

1
2
3

fetch_success = true
parse_success = false
error_type = selector_not_found

6. 用 BeautifulSoup 解析动态渲染后的内容

如果 HTML 中本来就没有目标数据，BeautifulSoup 也解析不出来。

这时要回到浏览器 Network 面板，看数据来自哪里。

可能是：

1
2
3
4

接口 JSON。
内嵌 script 状态。
前端异步请求。
浏览器渲染后的 DOM。

不要把“BeautifulSoup 没解析到”误判成“代码写错”。

十九、BeautifulSoup、XPath、正则怎么选？

简单比较：

工具适合场景
BeautifulSoupHTML 容错解析、标签查找、文本和属性提取
CSS Selector前端结构熟悉、class/id 选择清晰的页面
XPath层级复杂、需要父子兄弟轴关系的页面
正则文本片段、日期、金额、script 中局部模式
JSON 解析接口响应或 script 中完整 JSON 数据

建议顺序是：

1
2
3
4
5

能解析 JSON，就不要从 HTML 里扣。
HTML 结构清晰，可以用 BeautifulSoup / CSS Selector。
层级关系复杂，可以用 XPath。
局部文本模式适合正则。
动态渲染页面先找接口，再考虑浏览器自动化。

工具选择体现的是工程判断。

不是会的工具越多越好，而是能选对工具。

二十、面试表达

如果面试官问：

1

你怎么用 BeautifulSoup 解析网页？

可以这样回答：

我一般会先确认目标数据是否已经在 HTML 里，如果在，就用 BeautifulSoup 把 HTML 解析成文档对象。解析时不会全局乱找标签，而是先定位列表容器或详情页主体，再在局部范围内用 find、find_all 或 CSS Selector 提取标题、链接、时间、作者等字段。链接会用 urljoin 转成绝对地址，文本会用 get_text 处理空白，最终封装成 dataclass 或 Pydantic Schema，方便后续校验和入库。

如果问：

1

解析不到数据你怎么排查？

可以这样回答：

我会先区分是请求层问题还是解析层问题。先看状态码、最终 URL、Content-Type，确认拿到的不是登录页、错误页或空壳 HTML。然后检查目标数据是否在原始 HTML 中，如果数据来自 JS 异步接口，就不应该用 BeautifulSoup 硬解析。若数据在 HTML 中，再检查选择器是否命中、容器是否变化、字段是否变成可选字段，并记录解析到的 item 数量和缺失字段情况。

如果问：

1

BeautifulSoup 和正则有什么区别？

可以这样回答：

BeautifulSoup 是 HTML 解析器，适合按标签结构、属性和层级提取数据；正则适合从文本中提取局部模式，比如日期、金额、编号或 script 中的某个片段。对于结构化 HTML，我优先用 BeautifulSoup、CSS Selector 或 XPath，不会用正则硬解析整个 HTML。正则可以作为补充工具，但不应该替代 HTML 解析器。

二十一、总结

本文讲了 BeautifulSoup 在网页解析中的实战用法。

核心结论包括：

  • 拿到 HTML 不等于拿到数据，解析层负责把页面转成结构化字段。
  • BeautifulSoup 适合解析结构相对清晰、已经包含目标数据的 HTML。
  • find、find_all、select_one、select 是最常用的查找方式。
  • 文本提取要注意空白和分隔符，常用 get_text(" ", strip=True)。
  • 链接、图片、时间等很多字段来自标签属性，不只是文本。
  • 相对 URL 要用 urljoin 转成绝对 URL。
  • 解析结果应该封装成 dataclass 或 Pydantic Schema。
  • 可选字段可以为空，必填字段缺失应该记录或报错。
  • 解析失败要和请求失败分开记录。
  • 如果 HTML 中没有目标数据，要回到 Network 面板找接口或动态渲染来源。
