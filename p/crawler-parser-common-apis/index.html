1

3
4

3. 工程建议

实际项目里可以这样选：

1
2
3
4

简单结构优先 CSS Selector。

同一数据源内部尽量保持风格一致。

不推荐：

from bs4 import BeautifulSoup


def select_text(soup: BeautifulSoup, css: str) -> str | None:
    node = soup.select_one(css)
    if node is None:
        return None

    text = node.get_text(" ", strip=True)
    return text or None


def select_attr(soup: BeautifulSoup, css: str, attr: str) -> str | None:
    node = soup.select_one(css)
    if node is None:
        return None

    value = node.get(attr)
    return value.strip() if isinstance(value, str) and value.strip() else None

def select_texts(soup: BeautifulSoup, css: str) -> list[str]:
    values = []

    for node in soup.select(css):
        text = node.get_text(" ", strip=True)
        if text:
            values.append(text)

    return values


tags = select_texts(soup, "ul.tags li")

from dataclasses import dataclass
from bs4 import BeautifulSoup


@dataclass
class ParsedArticle:
    article_id: str | None
    title: str | None
    author: str | None
    published_at: str | None
    content: str | None
    tags: list[str]
    source_url: str | None


def parse_article(html: str) -> ParsedArticle:
    soup = BeautifulSoup(html, "lxml")

    article = soup.select_one("article.news-detail")
    article_id = article.get("data-id") if article else None

    paragraphs = select_texts(soup, "div.content p")
    content = "\n".join(paragraphs) if paragraphs else None

    return ParsedArticle(
        article_id=article_id,
        title=select_text(soup, "h1.title"),
        author=select_text(soup, "span.author"),
        published_at=select_text(soup, "span.date"),
        content=content,
        tags=select_texts(soup, "ul.tags li"),
        source_url=select_attr(soup, "a.source", "href"),
    )

def validate_parsed_article(article: ParsedArticle) -> list[str]:
    errors = []

    if not article.title:
        errors.append("title_missing")

    if not article.content:
        errors.append("content_empty")

    if not article.published_at:
        errors.append("published_at_missing")

    return errors

十一、与 LLM 抽取怎么配合？

LLM 不应该替代所有解析 API。

更合理的分工是：

4

BeautifulSoup / XPath / CSS Selector：提取稳定结构字段。

标题、发布时间、正文：优先规则抽取。

不要把整页 HTML 直接丢给模型。

更好的方式是：

先用解析 API 提取正文和基础字段。

十二、常见坑点

1. 直接 .text 不判空

错误写法：

1

节点不存在时会报错。

更稳妥：

1
2

node = soup.find("h1")
title = node.get_text(strip=True) if node else None

2. 选择器过深

过深路径容易失效。

尽量使用稳定语义节点：

1
2
3
4
5

article。

h1。

data-* 属性。

3. 过度依赖 class

有些站点 class 是构建产物，可能经常变化。

选择器要结合页面稳定特征。

4. 把空字段当成成功

解析函数没有报错，不代表结果可用。

必须做字段校验。

5. 不保存失败样本

选择器失效时，如果没有保存 HTML 样本，很难复盘。

建议保存：

缺失字段。
解析规则版本。

6. 正文提取没有去噪

导航、页脚、推荐区、广告区会污染正文。

十三、面试表达

如果面试官问：

1

BeautifulSoup 常用哪些 API？

可以这样回答：

常用的是 BeautifulSoup 初始化、find、find_all、select、select_one、get_text、get、attrs、decompose。工程中我会封装 select_text、select_attr 这类工具函数，统一处理节点缺失、空白清洗和属性读取。

如果问：

1

XPath 和 CSS Selector 怎么选？

可以这样回答：

CSS Selector 写法简洁，适合按 class、id 和层级定位；XPath 表达能力更强，适合按文本、属性、父子兄弟关系定位。工程中我会优先选择稳定、可读、不太依赖深层路径的选择器。

如果问：

1

解析字段缺失怎么办？

可以这样回答：

我不会只看代码是否报错，而会做字段级校验。比如 title、content 是关键字段，缺失就记录失败样本并进入复核；author 这类可选字段可以允许为空。还会监控字段缺失率，如果突然升高，可能是页面结构变化或返回了异常页面。

如果问：

1

lxml 和 BeautifulSoup 有什么区别？

可以这样回答：

BeautifulSoup 上手简单、容错性好，适合快速解析和处理不规范 HTML；lxml 性能更好，XPath 支持强，适合大规模和复杂结构抽取。实际项目里可以 BeautifulSoup 做简单解析，lxml 或 parsel 做 XPath / CSS 规则抽取。

如果问：

1

LLM 出现后还需要 XPath 吗？

可以这样回答：

需要。稳定字段应该优先用 XPath、CSS Selector、JSON 解析等确定性方法提取，成本低、速度快、可解释。LLM 更适合复杂正文理解、摘要、分类和语义字段。工程上应该规则优先，LLM 补充，而不是用 LLM 替代所有解析规则。

十四、总结

本文整理了网页解析模块常用 API。

核心结论包括：

  • BeautifulSoup 适合快速解析 HTML，常用 API 包括 find、find_all、select、select_one、get_text、get、attrs、decompose。
  • lxml 性能强，XPath 支持完整，适合复杂结构和大规模解析。
  • parsel 同时支持 CSS Selector 和 XPath，get / getall API 很适合爬虫抽取。
  • CSS Selector 简洁，适合 class、id、层级定位；XPath 表达力强，适合文本、属性和复杂关系定位。
  • 解析代码要判空，不要直接 .text 或 [0]。
  • 工程中应封装 select_text、select_attr、select_texts 等工具函数，统一处理缺失和清洗。
  • 解析结果要经过字段校验，不能因为代码没报错就认为成功。
  • 选择器失效要保存失败样本、记录缺失字段、监控解析成功率。
  • LLM 可以辅助语义抽取，但稳定字段仍应优先使用规则解析。
