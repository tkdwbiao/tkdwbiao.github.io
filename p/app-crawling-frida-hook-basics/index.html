大模型时代的数据采集工程 18：App 抓包与 Frida Hook 基础认知

2026-01-14 10:00
阅读时长: 12 分钟

上一篇文章里，我们讲了 AST 在 JavaScript 混淆分析中的应用。

重点是：

1
2
3

代码不只是字符串。
AST 可以帮助我们理解函数、变量、调用和结构。
混淆分析要保持授权和合规边界。

从这一篇开始，我们把视角从 Web 前端扩展到 App。

很多数据采集工程师都会遇到这样的问题：

1
2
3
4
5
6

Web 页面没有目标数据。
移动 App 里能看到数据。
App 请求接口和 Web 不一样。
参数来自移动端运行环境。
请求链路中有设备信息、登录态和加密字段。
抓包时看不到明文请求。

这就进入了 App 抓包与移动端分析领域。

但这个方向非常敏感。

所以本文必须先明确边界：

本文只讲 App 与 Web 采集的差异、Android 网络链路、抓包分析的基础概念、Frida Hook 的原理认知和合规测试场景；不提供绕过证书校验、破解接口、规避风控、还原真实 App 参数或未授权采集的操作流程。

一、前言

App 数据采集和 Web 数据采集很像，但又不完全一样。

Web 场景里，我们常见的链路是：

1
2
3
4
5

浏览器加载页面。
执行 JavaScript。
请求接口。
渲染 DOM。
从 HTML 或接口中提取数据。

App 场景里，链路变成：

1
2
3
4
5
6
7

App 启动。
读取设备和用户状态。
调用移动端 SDK 或业务代码。
构造请求参数。
发起 HTTPS 请求。
服务端返回 JSON / Protobuf / 图片 / 二进制数据。
App 渲染页面。

差异在于：

1
2
3
4
5

运行环境从浏览器变成 Android / iOS。
状态来源从 Cookie / localStorage 变成 App 存储、Token、设备信息。
请求逻辑可能在 Java / Kotlin / Native 层。
参数可能来自 SDK、系统 API、加密库。
调试方式也从 DevTools 变成抓包、日志、反编译、Hook 等工具。

这也是为什么 App 分析比 Web 更敏感。

它可能触及：

1
2
3
4
5
6
7

用户隐私。
设备标识。
账号安全。
通信安全。
证书校验。
风控系统。
商业接口。

因此，公开写作必须坚持：

1
2
3
4
5

机制理解。
授权测试。
自有系统排查。
安全审计。
合规边界。

而不是提供真实 App 的突破步骤。

二、App 采集和 Web 采集的区别

先看几个维度。

维度WebApp
运行环境浏览器Android / iOS
调试工具DevTools抓包工具、日志、反编译、Hook
状态存储Cookie、localStorage、SessionStorageSharedPreferences、SQLite、文件、KeyStore、Token
请求发起fetch、XHR、axiosOkHttp、Retrofit、URLConnection、Native SDK
页面渲染HTML / DOMNative View、Flutter、React Native、小程序容器
参数来源JS、页面状态、浏览器 APIApp 代码、设备信息、SDK、系统 API
安全机制CSRF、CORS、浏览器策略证书校验、设备绑定、签名校验、完整性检测

这说明 App 分析不能简单套用 Web 思路。

例如 Web 中你可以在 DevTools 里直接看 Network。

App 中则需要考虑：

1
2
3
4
5
6

请求是否经过系统代理。
是否使用 HTTPS。
是否有证书校验。
请求体是否压缩或二进制编码。
接口是否绑定设备和账号状态。
是否属于授权测试范围。

一个 Android App 发起网络请求，大致可能经过：

常见网络库包括：

Retrofit。
HttpURLConnection。
Volley。
自研网络 SDK。
Native 层网络库。

以 OkHttp 为例，业务代码可能不是直接写请求。

而是：

还要理解：

1

错误在哪一层处理？

这和 Webpack 里查找统一请求封装很像。

四、抓包是什么？

抓包是观察网络请求和响应的一种方式。

在授权测试中，抓包可以帮助确认：

1
2
3
4
5
6
7
8

App 请求了哪些域名。
接口路径是什么。
请求方法是什么。
状态码是什么。
响应格式是什么。
错误是否来自服务端。
登录态是否过期。
是否发生重定向。

常见抓包工具包括：

1
2
3
4
5

Charles。
Fiddler。
mitmproxy。
Wireshark。
Android Studio Network Profiler。

但要注意：

1
2
3

抓包必须限定在自有 App、授权测试环境或明确许可的安全测试中。
不要抓取他人账号、第三方敏感业务或无授权 App 的通信内容。
不要尝试绕过证书校验或访问控制。

在合规测试中，抓包通常用于：

1
2
3
4
5

验证自有 App 是否正确调用接口。
排查请求参数缺失。
确认错误码和日志是否一致。
检查是否传输了不该传的敏感字段。
验证 HTTPS 配置是否符合要求。

五、HTTPS 和证书校验的边界

App 通常通过 HTTPS 通信。

HTTPS 的作用包括：

1
2
3
4

加密传输。
防止中间人窃听。
验证服务端身份。
保护用户隐私和业务数据。

有些 App 还会使用证书绑定或更严格的校验机制。

它的目的通常是：

1
2
3

防止通信被篡改。
防止用户敏感数据被窃取。
提高账号和业务安全。

这里是非常重要的边界：

本文不提供绕过证书校验、证书绑定或安全通信保护的操作步骤。

在自有系统中，如果你需要做安全测试，应该通过：

1
2
3
4
5
6

测试环境。
调试构建。
专用测试证书。
服务端日志。
App 内部网络日志。
正式授权的安全测试流程。

来完成排查。

不要把保护用户安全的机制当成障碍。

六、Frida 是什么？

Frida 是一个动态插桩工具。

它可以在运行时观察和修改进程中的函数调用。

在安全研究和自有 App 测试中，Frida 常用于：

1
2
3
4
5
6

观察函数参数。
观察函数返回值。
验证某段代码是否被调用。
辅助定位崩溃或异常流程。
测试安全边界。
分析自有 SDK 行为。

Hook 的概念可以理解为：

1
2
3
4

在函数执行前后插入观察逻辑。
记录输入。
记录输出。
必要时在测试环境中改变行为。

例如在自有调试代码里，你可以把 Hook 理解成这样：

1
2
3
4
5
6
7
8
9

def original_function(value):
    return value * 2


def hooked_function(value):
    print("before", value)
    result = original_function(value)
    print("after", result)
    return result

这只是概念示例。

真实 Frida 用于 Android / iOS 进程，需要严格授权。

七、Hook 能解决什么问题？

在合规测试中，Hook 可以帮助排查：

1
2
3
4
5
6

某个方法是否被调用。
请求参数在进入网络层前是什么。
Token 是否在某个拦截器中加入。
某个 SDK 返回了什么值。
错误是业务层产生还是网络层产生。
加密函数输入输出是否符合自有系统预期。

例如自有 App 的测试场景：

1
2
3
4

测试账号登录后，接口仍然返回 401。
你怀疑 Token 没有正确写入 Header。
可以在测试环境中观察请求构造函数和拦截器。
确认 Token 是否为空、过期或格式错误。

这属于授权调试。

不是绕过。

八、Hook 不应该用于什么？

Hook 能力很强，因此边界必须明确。

不应该用于：

1
2
3
4
5
6

绕过证书校验。
绕过登录和权限控制。
规避验证码或风控系统。
破解付费接口。
提取他人账号或敏感数据。
批量放大未授权采集。

如果一个问题涉及访问控制或风控限制，正确路径是：

1
2
3
4
5
6

确认授权范围。
使用测试环境。
申请接口权限。
查看服务端日志。
联系系统负责人。
暂停自动化任务。

而不是继续尝试突破。

十、一个安全的本地 Hook 思维示例

为了理解 Hook 思维，我们不用真实 App。

只用 Python 模拟“函数观察”。

from functools import wraps


def trace_call(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("call", func.__name__, "args=", args, "kwargs=", kwargs)
        result = func(*args, **kwargs)
        print("return", func.__name__, "result=", result)
        return result

    return wrapper


@trace_call
def build_headers(token: str | None) -> dict[str, str]:
    headers = {"Accept": "application/json"}
    if token:
        headers["Authorization"] = f"Bearer {token}"
    return headers


build_headers("demo-token")

这个例子表达的是：

1
2
3

在函数前后观察输入和输出。
不改变业务逻辑。
用于调试和诊断。

真实 Hook 工具也是类似思路，只是目标变成运行中的 App 进程。

十一、抓包、日志和 Hook 怎么配合？

在授权测试中，三者各有作用。

1
2
3

抓包：观察网络层最终请求和响应。
日志：观察业务层状态和错误。
Hook：观察运行时函数调用和参数。

建议排查顺序：

1
2
3
4

1. 先看 App 日志和服务端日志。
2. 再看抓包确认网络请求。
3. 如果参数来源不清楚，再在测试环境中做 Hook 观察。
4. 涉及权限、证书、风控时，走授权流程或暂停。

不要一上来就 Hook。

很多问题通过日志和服务端排查就能解决。

十六、常见错误写法

1. 把 App 抓包当成默认采集方案

如果有正式 API、数据导出或服务端日志，优先使用这些方式。

抓包应该用于授权测试和诊断，不应该作为默认采集入口。

2. 不区分测试环境和生产环境

测试环境可控。

生产环境涉及真实用户和真实数据，必须更谨慎。

3. 忽略敏感字段脱敏

Token、设备 ID、手机号、位置、Cookie 等都可能是敏感信息。

日志和样本必须脱敏。

4. 一上来就 Hook

Hook 是强工具。

应先通过日志、服务端记录和抓包排查。

只有在授权测试中确有必要时，再使用 Hook 观察函数调用。

5. 试图绕过证书校验

证书校验保护用户通信安全。

公开文章和合规项目中不应提供绕过步骤。

6. 把 Frida 能力等同于采集能力

Frida 是动态分析工具，不是数据采集系统。

工程采集仍然需要授权、任务调度、限速、存储、清洗和审计。

十七、面试表达

如果面试官问：

1

App 抓包和 Web 抓包有什么区别？

可以这样回答：

Web 主要通过浏览器 DevTools 看 Network、Cookie、localStorage 和 JavaScript 调用链；App 则运行在 Android / iOS 环境中，请求可能经过 OkHttp、Retrofit、Native SDK 或统一网络层，状态可能来自本地存储、Token、设备信息和 SDK。App 抓包还涉及 HTTPS、证书校验、隐私数据和测试授权，所以边界更严格。

如果问：

1

Frida Hook 是什么？

可以这样回答：

Frida 是动态插桩工具，可以在运行时观察函数调用、参数和返回值。Hook 的思想是在函数执行前后插入观察逻辑，用于授权测试、调试和安全审计。比如在自有 App 中确认 Token 是否被正确加入 Header，或某个 SDK 方法是否被调用。但它不应该用于绕过证书校验、访问控制、验证码或风控系统。

1

App 接口请求失败你怎么排查？

可以这样回答：

我会先确认是否是自有或授权测试场景，再看 App 日志和服务端日志，确认请求是否到达服务端。然后看请求方法、URL、Header、Token、请求体格式和状态码。如果是登录态过期，就重新授权；如果是权限不足或风险限制，就暂停并人工确认；如果是自有 App 参数构造问题，可以在测试环境中通过日志、抓包或 Hook 观察调用链。

如果问：

1

移动端分析有哪些合规风险？

可以这样回答：

移动端分析可能涉及设备标识、账号凭证、位置、隐私数据、证书校验和风控规则，所以必须限定在自有 App 或授权测试对象中，使用测试账号和测试数据。日志要脱敏，不能抓取他人隐私数据，不能绕过证书校验或访问控制。遇到权限、风控或敏感数据问题，应暂停并走授权流程。

十八、总结

本文讲了 App 抓包与 Frida Hook 的基础认知。

核心结论包括：

  • App 采集和 Web 采集都涉及请求、状态和接口，但运行环境、状态来源和调试方式不同。
  • App 请求可能经过 OkHttp、Retrofit、URLConnection、Native SDK 或自研网络层。
  • 抓包用于授权测试和诊断，可以观察请求域名、路径、方法、状态码和响应格式。
  • HTTPS 和证书校验用于保护通信安全，本文不提供绕过证书校验的步骤。
  • Frida 是动态插桩工具，可以在授权场景中观察函数调用、参数和返回值。
  • Hook 的正当用途是自有系统调试、安全审计和测试验证，不是绕过访问控制或风控。
  • App 参数可能来自用户输入、Token、设备信息、App 版本、SDK、本地缓存和服务端配置。
  • 抓包、日志和 Hook 应配合使用，优先使用日志和服务端记录，必要时在授权测试中做 Hook 观察。
  • App 分析必须遵守隐私、授权、脱敏和审计要求。
  • LLM / Agent 可以辅助日志和错误诊断，但不能生成绕过证书、验证码或风控的策略。
