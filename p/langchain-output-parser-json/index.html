LangChain Output Parser：如何让大模型稳定输出 JSON？

2025-09-11 10:00
阅读时长: 12 分钟

前面我们已经学习了 PromptTemplate 和 LCEL，能写出这样的基础链路：

1

chain = prompt | model | parser

其中 prompt 负责组织任务，model 负责调用大模型，而 parser 负责处理模型输出。

很多初学者会忽略最后一步，觉得模型能回答就行。但在真实应用里，“能回答”远远不够。程序通常不希望拿到一大段自由文本，而是希望拿到稳定、可解析、可校验的数据结构。

比如你让模型生成文章选题，给人看可以是一段文字；但如果后端系统要继续保存到数据库、展示到页面、传给下一个链路，就更希望它输出 JSON。

这一篇，我们专门讲 LangChain 的 Output Parser 和结构化输出。

一、前言

大模型默认擅长生成自然语言。

比如你问：

1

请给我 3 个 LangChain 博客标题。

模型可能回答：

1
2
3
4

当然可以，下面是 3 个标题：
1. LangChain 入门：从模型调用到应用编排
2. 用 LangChain 构建你的第一个 RAG 应用
3. 从 Prompt 到 Agent：LangChain 核心模块解析

这对人类来说很好读，但对程序来说并不稳定。

如果你的系统希望拿到：

1
2
3
4
5
6
7

{
  "titles": [
    "LangChain 入门：从模型调用到应用编排",
    "用 LangChain 构建你的第一个 RAG 应用",
    "从 Prompt 到 Agent：LangChain 核心模块解析"
  ]
}

那就需要解决几个问题：

  1. 如何要求模型按格式输出？
  2. 如何把模型输出解析成 Python 对象？
  3. 如果模型输出格式不对怎么办？
  4. 什么时候用 Output Parser？
  5. 什么时候用新式 Structured Output？

本文会围绕这些问题展开。

二、为什么需要 Output Parser？

1. 自然语言对人友好，对程序不友好

人类读自然语言很舒服，但程序处理自然语言很痛苦。

比如模型输出：

1
2
3

标题一：LangChain 入门指南
标题二：PromptTemplate 实战
标题三：LCEL 编排详解

你可以用正则去提取，但很脆弱。

模型下次可能输出：

1
2
3
4

以下是我推荐的标题：
- LangChain 入门指南
- PromptTemplate 实战
- LCEL 编排详解

再下次可能输出：

1

我建议使用「LangChain 入门指南」「PromptTemplate 实战」「LCEL 编排详解」这三个标题。

人类都能看懂，但程序每次都要适配不同格式。

2. 应用链路需要稳定数据

真实大模型应用经常是多步骤链路。

例如：

1
2
3
4
5
6
7
8
9

模型生成文章选题
  ↓
程序解析标题、摘要、标签
  ↓
写入数据库
  ↓
展示到后台页面
  ↓
交给另一个模型生成正文

如果第一步输出不稳定，后面的链路都会受影响。

所以结构化输出不是锦上添花，而是工程落地的基础能力。

3. Prompt 约束不等于格式保证

很多人会在 Prompt 里写：

1

请严格输出 JSON，不要输出任何额外内容。

这有帮助，但不能百分百保证。

模型仍然可能输出：

1
2
3
4

好的，以下是 JSON：
{
  "title": "LangChain 入门"
}

或者漏掉引号、加上 Markdown 代码块、字段类型不对。

所以我们需要更系统的方案：

  • 通过 Prompt 提供格式指令
  • 通过 Parser 解析输出
  • 通过 Pydantic 或 schema 校验结构
  • 必要时使用模型原生结构化输出能力

三、Output Parser 的基本思路

Output Parser 的作用可以概括为：

把模型返回的内容转换成程序更容易处理的格式。

在 LangChain 里，Parser 通常放在链路末尾：

1

chain = prompt | model | parser

流程是：

1
2
3
4
5
6
7

Prompt 生成消息
  ↓
Model 生成回复
  ↓
Parser 解析回复
  ↓
返回字符串、字典或对象

常见 Parser 包括：

Parser作用
StrOutputParser把模型输出转成字符串
JsonOutputParser把模型输出解析成 JSON/Python dict
PydanticOutputParser按 Pydantic 模型解析并校验

需要注意：在新版 LangChain 实践中，结构化输出还可以通过 with_structured_output、模型原生 JSON schema、tool calling 或 agent 的 response_format 完成。

所以本文会同时讲传统 Output Parser 和现代 Structured Output 的关系。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名专业的 AI 应用开发讲师。"),
    ("human", "请用一句话解释：{topic}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.3,
)

parser = StrOutputParser()

chain = prompt | model | parser

result = chain.invoke({"topic": "LangChain Output Parser"})
print(type(result))
print(result)

这里 result 是普通字符串。

2. 什么时候用 StrOutputParser？

适合这些场景：

  • 生成文章
  • 生成摘要
  • 生成解释
  • 生成自然语言回答
  • 用户直接阅读模型输出

如果后续程序只需要展示文本，StrOutputParser 就够了。

但如果后续程序要读取字段，就应该考虑 JSON 或 Pydantic。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import JsonOutputParser

load_dotenv()

parser = JsonOutputParser()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名技术博客选题助手。请严格输出 JSON，不要输出 Markdown。"),
    ("human", "请为主题《{topic}》生成 3 个博客标题，格式为：{{\"titles\": [\"标题1\", \"标题2\", \"标题3\"]}}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    temperature=0.2,
)

chain = prompt | model | parser

result = chain.invoke({"topic": "LangChain RAG 入门"})

print(type(result))
print(result)
print(result["titles"])

2. 为什么 Prompt 里双大括号？

在 PromptTemplate 里，{topic} 表示变量。

如果你想在模板里展示 JSON 的大括号，就需要转义。

例如：

1

"格式为：{{\"titles\": [...]}}"

这里的 {{ 和 }} 表示输出字面量 { 和 }。

这是写 JSON Prompt 时常见的坑。

3. JsonOutputParser 的局限

JsonOutputParser 可以解析 JSON，但它不能天然保证业务字段完全符合你的要求。

比如你想要：

1

5

{
  "title": "...",
  "difficulty": "beginner",
  "tags": ["LangChain", "RAG"]
}

模型可能输出：

1
2
3
4
5

{
  "title": "...",
  "difficulty": "入门",
  "tag": "LangChain"
}

JSON 是合法的，但字段名和字段类型不符合预期。

这时候就需要更强的结构校验。

六、PydanticOutputParser：用 Schema 约束输出

Pydantic 是 Python 中非常常用的数据校验库。

我们可以用 Pydantic 定义模型输出结构，然后让 Parser 按这个结构解析。

import os
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import PydanticOutputParser

load_dotenv()

class BlogIdea(BaseModel):
    title: str = Field(description="博客标题")
    summary: str = Field(description="100 字以内的摘要")
    tags: list[str] = Field(description="文章标签")
    difficulty: str = Field(description="难度级别：beginner、intermediate、advanced")

parser = PydanticOutputParser(pydantic_object=BlogIdea)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名专业的技术博客策划助手。"),
    ("human", """
请为主题《{topic}》生成一个博客选题。

{format_instructions}
"""),
])

prompt = prompt.partial(format_instructions=parser.get_format_instructions())

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    temperature=0.2,
)

chain = prompt | model | parser

result = chain.invoke({"topic": "LangChain Output Parser"})

print(type(result))
print(result.title)
print(result.tags)

这里的 result 不再是普通字典，而是 BlogIdea 对象。

3. get_format_instructions() 是什么？

parser.get_format_instructions() 会生成一段格式说明，告诉模型应该按什么结构输出。

我们把它放进 Prompt：

1

prompt = prompt.partial(format_instructions=parser.get_format_instructions())

这样模型不仅知道任务，还知道输出结构。

4. PydanticOutputParser 的价值

它解决的是“字段结构”和“类型校验”的问题。

如果模型输出缺字段、字段类型错误、JSON 不合法，就可能解析失败。

这比默默得到错误数据要好，因为错误会在链路中尽早暴露。

然后直接调用：

import os
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from langchain_openai import ChatOpenAI

load_dotenv()

class BlogIdea(BaseModel):
    title: str = Field(description="博客标题")
    summary: str = Field(description="100 字以内摘要")
    tags: list[str] = Field(description="文章标签")

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    temperature=0,
)

structured_model = model.with_structured_output(BlogIdea)

result = structured_model.invoke(
    "请为主题《LangChain 结构化输出》生成一个技术博客选题。"
)

print(type(result))
print(result.title)
print(result.summary)
print(result.tags)

它和 Output Parser 有什么区别？

可以粗略理解为：

  • Output Parser：模型先生成文本，再由 Parser 解析。
  • Structured Output：模型调用层就尽量按 schema 生成结构化结果。

在支持结构化输出的模型上，with_structured_output 往往更稳。

但不是所有模型、所有服务商、所有兼容 API 都同等支持这个能力。所以在实际项目里要根据模型能力选择。

八、Output Parser 与 Structured Output 怎么选？

可以参考下面的判断。

场景推荐方式
只需要文本StrOutputParser
简单 JSON，字段要求不复杂JsonOutputParser
需要字段类型校验PydanticOutputParser 或 with_structured_output
模型原生支持结构化输出优先 with_structured_output
Agent 最终响应需要结构化使用 agent 的 response_format / structured output
兼容模型结构化能力不稳定Parser + 校验 + 重试

我的建议是：

  1. 学习阶段先理解 Output Parser。
  2. 项目阶段优先调研模型是否支持原生结构化输出。
  3. 关键业务场景一定要做校验和错误处理。

import os
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import PydanticOutputParser

load_dotenv()

class BlogIdea(BaseModel):
    title: str = Field(description="文章标题")
    slug: str = Field(description="英文 URL slug，使用小写字母和连字符")
    summary: str = Field(description="文章摘要，100 字以内")
    tags: list[str] = Field(description="文章标签，3 到 5 个")
    target_reader: str = Field(description="目标读者")
    difficulty: str = Field(description="难度：beginner、intermediate、advanced")

parser = PydanticOutputParser(pydantic_object=BlogIdea)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名专业的技术博客策划专家，擅长为 AI 应用开发主题设计文章。"),
    ("human", """
请围绕主题《{topic}》生成一个适合技术博客的选题。

要求：
1. 标题清晰，不要标题党。
2. 摘要要说明文章能解决什么问题。
3. 标签要适合 Hugo 博客。
4. 难度只能是 beginner、intermediate、advanced 之一。

{format_instructions}
"""),
])

prompt = prompt.partial(format_instructions=parser.get_format_instructions())

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.2,
)

chain = prompt | model | parser

if __name__ == "__main__":
    idea = chain.invoke({"topic": "LangChain Output Parser"})

    print("标题：", idea.title)
    print("Slug：", idea.slug)
    print("摘要：", idea.summary)
    print("标签：", idea.tags)
    print("读者：", idea.target_reader)
    print("难度：", idea.difficulty)

这个例子已经很接近真实业务：模型不是随便生成一段话，而是生成一个可以被程序继续使用的对象。

十、解析失败怎么办？

结构化输出不是魔法。模型仍然可能输出不符合要求的内容。

常见失败包括：

  • JSON 格式错误
  • 缺少字段
  • 字段类型不对
  • 输出了 Markdown 代码块
  • 输出了额外解释文字
  • 枚举值不符合要求

1. 最简单的处理方式：捕获异常

1
2
3
4

try:
    result = chain.invoke({"topic": "LangChain"})
except Exception as e:
    print("解析失败：", e)

这至少能避免程序直接崩溃。

2. 降低 temperature

结构化输出场景通常不需要太高随机性。

1
2
3
4

model = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0,
)

temperature=0 往往更稳定。

3. Prompt 中明确禁止额外内容

1

只输出符合 schema 的 JSON，不要输出 Markdown，不要输出解释文字。

这不能保证百分百成功，但有帮助。

4. 使用模型原生结构化输出

如果模型支持 with_structured_output 或 JSON schema，优先使用。

5. 关键业务要设计重试和兜底

比如：

  • 第一次解析失败后重试
  • 把错误信息反馈给模型修复
  • 记录失败样本用于优化 Prompt
  • 对关键字段做二次校验

后续工程化篇会继续讨论这些问题。

十一、常见问题

1. 只在 Prompt 里写“输出 JSON”够吗？

不够。

这只是软约束。模型可能不完全遵守。

更稳的方式是结合：

  • 格式指令
  • Output Parser
  • Pydantic schema
  • 模型原生结构化输出
  • 错误处理和重试

2. JsonOutputParser 和 PydanticOutputParser 有什么区别？

JsonOutputParser 主要保证结果能解析成 JSON。

PydanticOutputParser 会进一步按 Pydantic 模型校验字段和类型。

如果你的业务只要字典，JsonOutputParser 可以；如果字段结构很重要，Pydantic 更合适。

3. Structured Output 是否能完全替代 Output Parser？

不一定。

如果你的模型和服务商原生支持结构化输出，优先用它。

但在一些兼容 API、本地模型或旧模型场景下，Output Parser 仍然有价值。

4. 为什么模型输出了合法 JSON，Parser 还是失败？

可能是：

  • 字段类型不符合 Pydantic 定义
  • 缺少必填字段
  • 输出结构是数组，但你期望对象
  • 字段名不一致
  • 外层包了一层多余字段

合法 JSON 不等于合法业务对象。

5. 结构化输出是不是越复杂越好？

不是。

Schema 越复杂，模型越容易出错。

建议从简单结构开始，必要时再增加字段。

十二、最佳实践

1. 结构越简单越稳定

不要一上来要求模型输出几十个字段。

先从核心字段开始：

1
2
3

title: str
summary: str
tags: list[str]

稳定后再扩展。

2. 字段描述要明确

Pydantic 的 Field(description=...) 很重要。

不要写：

1

summary: str = Field(description="summary")

更好：

1

summary: str = Field(description="100 字以内的中文摘要，说明文章解决什么问题")

描述越明确，模型越容易输出正确。

3. 结构化任务降低 temperature

创意写作可以高一点，结构化输出建议低一点。

1

temperature=0

或者：

1

temperature=0.2

4. 不要盲目信任模型输出

即使 Parser 成功，也要做业务校验。

例如：

  • slug 是否符合 URL 规则
  • tags 是否超过数量限制
  • difficulty 是否在枚举范围内
  • summary 是否过长

5. 生产环境记录解析失败样本

解析失败不是坏事，它是优化数据。

应该记录：

  • 输入
  • Prompt
  • 原始模型输出
  • 解析错误
  • 模型名称
  • 时间和调用参数

这些信息能帮助你持续优化 Prompt 和 schema。

十三、总结

本文我们讲了 LangChain 的 Output Parser 和结构化输出。

核心结论是：

大模型输出自然语言很容易，但工程应用需要稳定、可解析、可校验的数据结构。

本文重点包括：

  • StrOutputParser 适合普通文本输出。
  • JsonOutputParser 可以把模型输出解析成 JSON。
  • PydanticOutputParser 可以按 schema 校验字段和类型。
  • with_structured_output 是现代 LangChain 中更推荐关注的结构化输出方式之一。
  • Prompt 里的“请输出 JSON”只是软约束，不能替代解析和校验。
  • 结构化输出越关键，越要设计错误处理、重试和日志记录。

到这里，我们已经掌握了 LangChain 应用链路里的一个关键环节：把模型输出变成程序可消费的数据。

下一篇文章，我们会继续深入 Runnable 机制，系统拆解 RunnableSequence、RunnableParallel、RunnableLambda、assign、bind、with_config 和 with_retry。理解这些底层抽象后，你会更清楚 LCEL 为什么能支撑复杂的大模型应用编排。
