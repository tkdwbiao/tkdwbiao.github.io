从 O(NK) 到 O(NlogK)：合并 K 个升序链表的三重境界

2026-04-01 20:26
阅读时长: 3 分钟

[LeetCode 23. 合并 K 个升序链表] 是链表题目中的终极挑战。它考察的不仅是基本的指针操作，更是对“如何从多个候选人中快速选出最小者”的算法思考。

今天阿彪带大家拆解三种境界的解法：顺序迭代、两两分治、最小堆优化。

一、 境界一：顺序迭代（滚雪球法）

1. 思想 (Idea)

既然我们会合并两个链表（LeetCode 21），那合并 $K$ 个还不简单？ 先合并第 1 和第 2 个，拿到的结果再和第 3 个合并，以此类推。

2. 过程 (Process)

  1. 编写一个基础函数 mergeTwoLists(l1, l2)。
  2. 维护一个 ans 链表，初始为 lists[0]。
  3. 循环 $K-1$ 次，不断将 ans 与下一个链表合并。

class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        if not lists: return None
        
        # 复用合并两个有序链表的逻辑
        def merge2Lists(l1, l2):
            dummy = ListNode(0)
            curr = dummy
            while l1 and l2:
                if l1.val < l2.val:
                    curr.next, l1 = l1, l1.next
                else:
                    curr.next, l2 = l2, l2.next
                curr = curr.next
            curr.next = l1 if l1 else l2
            return dummy.next

        # 顺序合并
        ans = None
        for l in lists:
            ans = merge2Lists(ans, l)
        return ans
  • 复杂度：时间 $O(N \cdot K)$，空间 $O(1)$。
  • 反思：这比“扫街查找法”好一点，但还是慢。因为 ans 链表会越滚越大，后面的合并操作负担极重。

二、 境界二：分治合并（锦标赛法）

1. 思想 (Idea)

与其让一个人干所有的活，不如大家分头行动。 采用 归并排序（Merge Sort） 的思路：把 $K$ 个链表对半拆分，分别合并，最后再把两个大链表合在一起。

2. 过程 (Process)

  1. 这是一个“两两配对”的过程。
  2. 第一轮：1和2合，3和4合… 剩下 $K/2$ 个链表。
  3. 第二轮：继续对半合，直到只剩一个。

class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        if not lists: return None
        n = len(lists)
        
        interval = 1
        while interval < n:
            # 两两一组进行合并
            for i in range(0, n - interval, interval * 2):
                lists[i] = self.merge2Lists(lists[i], lists[i + interval])
            interval *= 2

三、 境界三：最小堆优化（自动排序法）🌟

1. 思想 (Idea)

这是工业界最推崇的写法。我们不需要反复合并，我们只需要一个**“自动筛选最小值”**的漏斗。 将每个链表的“头”放进小顶堆，每次吐出来的肯定是全局最小。

2. 过程 (Process)

  1. 初始：把 $K$ 个头节点压入堆。
  2. 弹出堆顶（最小值），接入结果。
  3. 补充：谁被弹出了，就把谁的 next 再压入堆。

import heapq

class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        hp = []
        # 1. 初始入堆：(值, 索引, 节点对象)
        # 存索引是为了避开 Python 比较 ListNode 对象的坑
        for i, head in enumerate(lists):
            if head: heapq.heappush(hp, (head.val, i, head))
        
        dummy = ListNode(0)
        curr = dummy
        
        while hp:
            val, idx, node = heapq.heappop(hp)
            curr.next = node
            curr = curr.next
            # 2. 补充入堆
            if node.next:
                heapq.heappush(hp, (node.next.val, idx, node.next))
                
        return dummy.next
  • 复杂度：时间 $O(N \log K)$，空间 $O(K)$。

四、 阿彪的深度总结 [抱拳]

1. 三种方法怎么选？

方法时间复杂度空间复杂度适用场景
顺序迭代$O(NK)$$O(1)$逻辑最简单，$K$ 小时可用
两两分治$O(N \log K)$$O(1)$面试官最想看的极致空间优化
最小堆$O(N \log K)$$O(K)$处理流式数据、最符合直觉的优化

2. 阿彪的细节纠错

  • 堆的坑：Python 的 heapq 比较元组时，如果第一位（val）相等，会比第二位。如果你不存 i 而是直接存 (val, node)，它会尝试比较两个 ListNode，这会报错！
  • 分治的坑：在写 while interval < n 时，注意 lists[i] 的覆盖顺序。

从 $O(NK)$ 的蛮力到 $O(N \log K)$ 的灵动，算法的魅力就在于对数据结构的精准打击。阿彪祝大家 Offer 永不断链！
