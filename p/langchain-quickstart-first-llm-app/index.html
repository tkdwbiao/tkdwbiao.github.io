LangChain 快速开始：搭建你的第一个大模型应用

2025-09-05 10:00
阅读时长: 12 分钟

前两篇文章里，我们先后解决了两个问题：

  1. 为什么需要 LangChain 这样的大模型应用开发框架。
  2. LangChain 的核心模块之间是什么关系。

现在，是时候真正动手了。

这一篇我们不再只讲概念，而是从零搭建一个最小可运行的 LangChain 项目：安装 Python 环境、管理 API Key、调用第一个 Chat Model，再把 Prompt、Model 和 Output Parser 串成一条最基础的链。

你会看到，LangChain 的入门并不复杂。真正重要的是：从第一天开始，就用一种可维护的方式组织你的大模型应用。

一、前言

学习任何框架，最怕两种情况。

第一种是只看概念，迟迟不动手。看起来都懂，但一写代码就卡在环境、依赖、API Key 和版本问题上。

第二种是一上来就堆复杂项目。还没理解 Model、Prompt、Parser 的关系，就直接上 RAG、Agent、LangGraph，最后代码能跑，但完全不知道每一步为什么存在。

所以本文的目标很明确：

用最小成本跑通第一个 LangChain 大模型应用，并建立一个后续可以继续扩展的项目骨架。

本文会完成这几件事：

  1. 准备 Python 环境。
  2. 安装 LangChain 相关依赖。
  3. 配置 API Key。
  4. 完成第一次 Chat Model 调用。
  5. 使用 PromptTemplate 管理提示词。
  6. 使用 LCEL 串起 prompt | model | parser。
  7. 加入流式输出和批量调用示例。
  8. 总结常见报错和最佳实践。

如果你能顺利跑通本文代码，后续学习 Prompt、LCEL、Memory、RAG 和 Agent 时，就会轻松很多。

二、为什么要先搭建一个最小项目？

很多人第一次写大模型应用时，会直接在一个 Python 文件里写：

import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "你好"}],
)

print(response.choices[0].message.content)

这当然可以跑。

但如果我们要学习 LangChain，不能只停留在“调用模型”这一层。我们需要从一开始就意识到：真实项目里，模型调用只是链路中的一个节点。

一个可维护的大模型应用，至少要考虑：

  • 依赖如何管理？
  • API Key 放在哪里？
  • Prompt 如何复用？
  • 模型参数如何配置？
  • 输出结果如何解析？
  • 后续如何加入 RAG、Tool 和 Agent？
  • 代码如何从 demo 演进成项目？

所以，本文不是为了炫技，而是为了打好地基。

我们先搭一个非常小的项目，但这个项目要具备继续扩展的能力。

三、环境准备

1. Python 版本建议

根据 LangChain 当前官方安装文档，LangChain Python 推荐使用 Python 3.10 及以上版本。

你可以先检查本机 Python 版本：

1

python --version

或者：

1

python3 --version

如果输出类似：

1

Python 3.11.8

就可以继续。

如果你的 Python 版本低于 3.10，建议先升级。对于 Windows 用户，可以从 Python 官网安装新版本，也可以使用 Conda、uv、pyenv-win 等工具管理 Python 版本。

2. 创建项目目录

我们先创建一个单独的练习项目，不要把实验代码直接混进博客仓库里。

1
2

mkdir langchain-quickstart
cd langchain-quickstart

如果你在 Windows PowerShell 中，也可以这样：

1
2

mkdir langchain-quickstart
cd langchain-quickstart

3. 创建虚拟环境

推荐为每个 Python 项目创建独立虚拟环境，避免依赖污染。

macOS / Linux：

1
2

python -m venv .venv
source .venv/bin/activate

Windows PowerShell：

1
2

python -m venv .venv
.\.venv\Scripts\Activate.ps1

Windows CMD：

1
2

python -m venv .venv
.venv\Scripts\activate.bat

激活成功后，终端前面通常会出现：

1

(.venv)

这表示你已经进入虚拟环境。

4. 升级 pip

1

python -m pip install --upgrade pip

这一步不是必须，但建议做。很多安装问题都和旧版 pip 有关。

四、安装 LangChain 依赖

LangChain 现在采用比较模块化的包结构。

常见几个包是：

包名作用
langchainLangChain 主包，包含高层应用组件
langchain-core核心抽象，例如 messages、runnables、prompts、output parsers
langchain-openaiOpenAI 及兼容 OpenAI 接口的模型集成
python-dotenv从 .env 文件加载环境变量

最小安装可以这样：

1

pip install -U langchain langchain-openai python-dotenv

安装完成后，可以检查：

1
2

pip show langchain
pip show langchain-openai

如果能看到版本信息，说明安装成功。

为什么要单独安装 langchain-openai？

早期很多教程会写：

1

from langchain.chat_models import ChatOpenAI

或者：

1

from langchain_community.chat_models import ChatOpenAI

但在当前版本实践中，更推荐使用独立集成包：

1

from langchain_openai import ChatOpenAI

这也是官方文档中当前推荐的导入方式。

所以你看旧教程时要注意版本差异。如果照着旧导入路径写，可能会遇到弃用提示或导入错误。

五、配置 API Key

大模型应用通常需要 API Key。不要把 API Key 直接写进代码里。

错误示例：

1

api_key = "sk-xxxxxxxxxxxxxxxx"

这种写法很危险，一旦提交到 Git 仓库，就可能泄露。

更推荐用环境变量或 .env 文件。

1. 使用环境变量

macOS / Linux：

1

export OPENAI_API_KEY="你的 API Key"

Windows PowerShell：

1

$env:OPENAI_API_KEY="你的 API Key"

Windows CMD：

1

set OPENAI_API_KEY=你的 API Key

设置后，可以简单检查：

macOS / Linux：

1

echo $OPENAI_API_KEY

PowerShell：

1

echo $env:OPENAI_API_KEY

2. 使用 .env 文件

在项目根目录创建 .env 文件：

1

OPENAI_API_KEY=你的 API Key

如果你使用兼容 OpenAI API 的服务，还可以加上：

1
2
3

OPENAI_API_KEY=你的 API Key
OPENAI_BASE_URL=https://你的模型服务地址/v1
MODEL_NAME=gpt-4o-mini

注意：.env 文件不要提交到 Git。

建议创建 .gitignore：

1
2
3
4

.venv/
.env
__pycache__/
*.pyc

API Key 管理是大模型应用工程化的第一课。模型可以换，框架可以换，但密钥绝不能乱放。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

load_dotenv()

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    temperature=0.5,
)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名擅长讲解复杂技术概念的 AI 工程师。"),
    ("human", "请用适合初学者的方式解释：{topic}"),
])

messages = prompt.invoke({"topic": "LangChain 的核心价值"})
response = model.invoke(messages)

print(response.content)

运行：

1

这里发生了什么？

1
2
3
4

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名擅长讲解复杂技术概念的 AI 工程师。"),
    ("human", "请用适合初学者的方式解释：{topic}"),
])

我们把 prompt 拆成了两类消息：

  • system：设定模型角色和行为方式。
  • human：表达用户的具体问题。

{topic} 是变量，后续通过：

1

prompt.invoke({"topic": "LangChain 的核心价值"})

进行填充。

这种写法比字符串拼接更清晰，也更适合后续复用。

  • Prompt

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名专业的 AI 应用开发讲师。"),
    ("human", "请用三段话解释 {topic}，并给一个实际应用场景。"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    temperature=0.5,
)

parser = StrOutputParser()

chain = prompt | model | parser

result = chain.invoke({"topic": "LangChain"})

print(result)

运行：

1

python chain_demo.py

这就是 LangChain 非常经典的写法：

1

chain = prompt | model | parser

它表示一条执行链：

1

输入变量 → Prompt 生成消息 → Model 生成回复 → Parser 转成字符串

这就是 LCEL 的基本思想。

为什么这一步很重要？

因为后续你会不断遇到类似结构：

1

chain = retriever | prompt | model | parser

或者：

1
2
3
4

chain = {
    "context": retriever,
    "question": RunnablePassthrough(),
} | prompt | model | parser

所以现在先理解 prompt | model | parser，后面学习 RAG 和 Agent 时就不会突然断层。

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名耐心的技术讲师。"),
    ("human", "请用通俗语言解释 {topic}，适合初学者阅读。"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    temperature=0.6,
)

chain = prompt | model | StrOutputParser()

for chunk in chain.stream({"topic": "什么是 RAG"}):
    print(chunk, end="", flush=True)

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名技术博客作者。"),
    ("human", "请用 100 字以内解释：{topic}"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    temperature=0.3,
)

chain = prompt | model | StrOutputParser()

inputs = [
    {"topic": "PromptTemplate"},
    {"topic": "LCEL"},
    {"topic": "Retriever"},
]

results = chain.batch(inputs)

for topic, result in zip(inputs, results):
    print("=" * 40)
    print(topic["topic"])
    print(result)

运行：

1

batch 的意义不只是“帮你写循环”。它属于 Runnable 统一接口的一部分。后续结合并发、配置、重试时，它会比手写循环更自然。

十一、支持兼容 OpenAI API 的模型服务

很多模型服务都兼容 OpenAI API 格式，例如一些云模型平台或本地模型网关。

如果你的服务提供了兼容 OpenAI 的接口，可以通过 base_url 配置。

不过要注意：不同模型虽然接口兼容，但能力不一定完全一致。比如：

  • 结构化输出稳定性不同
  • 多模态能力不同
  • 价格和速度不同

所以在生产项目中，换模型之前一定要做测试。

十三、常见问题

1. ModuleNotFoundError: No module named 'langchain_openai'

说明你没有安装 langchain-openai，或者当前终端没有进入正确的虚拟环境。

解决：

1

pip install -U langchain-openai

然后确认虚拟环境已激活。

2. OPENAI_API_KEY not found

说明环境变量没有配置成功。

如果使用 .env，确认：

  1. .env 文件在当前 Python 脚本运行目录下。
  2. 文件名就是 .env，不是 .env.txt。
  3. 代码里调用了 load_dotenv()。
  4. 变量名是 OPENAI_API_KEY。

3. 401 Unauthorized

通常是 API Key 错误或没有权限。

检查：

  • API Key 是否复制完整。
  • 当前账号是否有模型调用权限。
  • 是否使用了错误的 base_url。
  • 代理或网关是否配置正确。

4. 连接超时或网络错误

可能原因：

  • 网络无法访问模型服务。
  • 代理配置错误。
  • base_url 写错。
  • 模型服务暂时不可用。

可以先用模型服务官方的最小示例测试，再回到 LangChain。

5. 旧教程里的导入路径不能用

如果你看到旧教程写：

1

from langchain.chat_models import ChatOpenAI

或者：

1

from langchain_community.chat_models import ChatOpenAI

现在更推荐改成：

1

from langchain_openai import ChatOpenAI

LangChain 生态变化比较快，学习时要优先看官方文档和最近版本的示例。

6. 模型输出每次都不一样

这是正常的。

如果你希望输出更稳定，可以降低 temperature：

1
2
3
4

model = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0,
)

如果你做创意写作，可以适当提高：

1

temperature=0.7

但不要以为 temperature 越高越聪明，它只是让输出更随机。

十四、最佳实践

1. 不要把 API Key 写进代码

这一条非常重要。

推荐顺序：

  1. 本地开发使用 .env。
  2. 部署环境使用环境变量或密钥管理服务。
  3. .env 必须加入 .gitignore。

2. 从第一天开始使用 PromptTemplate

不要等 prompt 变得复杂之后才重构。

1

这样后续加入 system message、变量、历史消息都会更自然。

  • stream：流式输出

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名专业、耐心、擅长用例子讲解技术的 AI 应用开发讲师。"),
    ("human", "请面向初学者解释 {topic}，并给出一个实际应用例子。"),
])

model = ChatOpenAI(
    model=os.getenv("MODEL_NAME", "gpt-4o-mini"),
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL") or None,
    temperature=0.5,
)

parser = StrOutputParser()

chain = prompt | model | parser

if __name__ == "__main__":
    result = chain.invoke({"topic": "LangChain"})
    print(result)

  • 包装成 Web API
  • 增加工具调用
  • 演进成 Agent

这就是我们学习 LangChain 的正确打开方式：先把地基打稳，再一层层往上盖。
